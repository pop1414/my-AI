## 02-文档列表与管理台

### 摘要

在 V1.1 中新增"文档列表"作为 `ingest` 管理主入口，解决当前所有操作都依赖手填 `documentId` 的问题。第一版采用"列表主入口 + 行内跳转 + 复用现有功能页"的策略，不新增复杂详情页，不重做现有状态/预览/重处理/删除能力。该主题依赖知识库主数据化成果，前端 `kbId` 下拉选项复用 `GET /api/v1/knowledge-bases` 接口。

### 关键实现

- 前端控制台新增 `/ingest/documents` 页面，并把它放到 `ingest` 区域的首要入口；控制台默认落点从上传页调整为文档列表页。上传页仍保留为独立导航入口，不与列表页合并。
- 列表页提供轻量过滤：
    - `kbId`：下拉选择，选项复用已知知识库接口 `GET /api/v1/knowledge-bases`，仅展示 `ACTIVE` 知识库
    - `status`：单选框，可选值 `UPLOADED / INGESTING / INDEXED / FAILED / DELETING / DELETED`
    - `filename`：文本输入，模糊匹配
    - 默认按 `createdAt` 倒序排列，V1.1 不支持列头点击切换排序字段
    - 默认隐藏 `DELETED` 状态文档；显式选择 `status=DELETED` 可查看已删除文档
- 列表表格首版展示列：`documentId`、`kbId`、`filename`、`fileSize`、`status`、`updatedAt`。`failureReason` 仅在 `status=FAILED` 时以 Tooltip 或简短辅助文案展示，非失败态不展示该列内容。
- 列表操作采用"行内跳转"而不是行内执行，所有跳转均通过 URL 路径参数传递 `documentId`，不依赖内存状态（如 localStorage 或 React Router state）：
    - `查看状态`：跳到 `/ingest/documents/{documentId}/status`
    - `分块预览`：仅对 `INDEXED` 显示，跳到 `/ingest/documents/{documentId}/chunks-preview`
    - `重处理`：仅对 `FAILED / INDEXED` 显示，跳到 `/ingest/documents/{documentId}/reprocess`
    - `删除`：对非 `DELETING / DELETED` 显示，跳到 `/ingest/documents/{documentId}/delete`
- 现有 `status / chunks-preview / reprocess / delete` 页面继续保留，URL 路径与上述跳转目标保持一致。V1.1 不新增独立"文档详情页"或抽屉详情。

### 接口与数据

- 新增分页列表接口：`GET /api/v1/documents`
- 请求参数与校验规则：

| 参数       | 类型   | 必填 | 默认值         | 校验规则                                                                              |
| ---------- | ------ | ---- | -------------- | ------------------------------------------------------------------------------------- |
| `kbId`     | string | 否   | —              | 精确匹配；传入不存在的 `kbId` 返回空列表而非 400                                      |
| `status`   | string | 否   | 排除 `DELETED` | 仅接受 `UPLOADED / INGESTING / INDEXED / FAILED / DELETING / DELETED`，非法值返回 400 |
| `filename` | string | 否   | —              | 模糊匹配（LIKE %value%），最大 200 字符                                               |
| `limit`    | int    | 否   | `20`           | 范围 `[1, 100]`，超范围返回 400                                                       |
| `offset`   | int    | 否   | `0`            | `≥ 0`，负值返回 400                                                                   |

- 默认行为：当未传 `status` 时，后端查询自动附加 `status != 'DELETED'` 条件；显式传 `status=DELETED` 时才返回已删除文档。
- 响应体统一为分页包装：

```json
{
	"items": [],
	"total": 123,
	"limit": 20,
	"offset": 0
}
```

- `items` 每项字段定义：

| 字段            | 类型           | 说明                                                                   |
| --------------- | -------------- | ---------------------------------------------------------------------- |
| `documentId`    | string         | 文档资产标识                                                           |
| `kbId`          | string         | 所属知识库标识                                                         |
| `filename`      | string         | 原始文件名                                                             |
| `fileSize`      | long           | 文件字节数                                                             |
| `status`        | string         | 当前处理状态                                                           |
| `failureReason` | string \| null | 失败原因；仅 `status=FAILED` 时返回实际原因字符串，其余状态返回 `null` |
| `createdAt`     | string         | 创建时间（ISO-8601）                                                   |
| `updatedAt`     | string         | 最后更新时间（ISO-8601）                                               |

- 后端查询直接复用 `ingest_documents` 作为读模型来源；不为该主题新增主表。
- 读路径新增独立查询用例与查询仓储，不将分页列表查询逻辑混入现有命令型仓储（如 `IngestDocumentRepository` 中已有的 CAS 更新方法）。

### 测试计划

- 后端单元/集成：
    - 列表默认排除 `DELETED`，`status=DELETED` 可单独查到已删除文档
    - `kbId / status / filename` 单条件过滤及组合过滤均生效
    - 传入不存在的 `kbId` 返回空列表（`items=[]`，`total=0`），不返回 400
    - `filename` 模糊匹配：部分匹配命中，不匹配返回空列表
    - `createdAt DESC` 排序正确（最新文档在最前）
    - 分页边界：`limit=1` 返回单条，`offset` 超出 `total` 返回空列表
    - 非法参数校验：
        - `limit=0` / `limit=101` / `limit=-1` → 400
        - `offset=-1` → 400
        - `status=INVALID_VALUE` → 400
    - `failureReason`：`FAILED` 文档返回非空字符串，`INDEXED / UPLOADED` 等文档返回 `null`
- 前端：
    - 新路由 `/ingest/documents` 可正常访问，控制台默认跳转正确
    - `kbId` 下拉选项从知识库接口加载，仅展示 `ACTIVE` 知识库
    - 过滤条件提交后正确刷新列表，分页切换保持筛选条件
    - 行内操作按钮按状态正确显示/隐藏（预览仅 `INDEXED`、重处理仅 `FAILED/INDEXED`、删除排除 `DELETING/DELETED`）
    - 点击行内按钮跳转到对应页面，URL 携带正确的 `documentId`
    - `failureReason` 列仅在 `FAILED` 行展示，其余行不展示
- 集成验收：
    - 上传新文档后，在列表第一页能看到该文档（`status=UPLOADED` 或后续状态）
    - `FAILED / INDEXED` 文档可从列表进入重处理页
    - `INDEXED` 文档可从列表进入分块预览页
    - 删除文档后，默认列表不再显示该文档；切换 `status=DELETED` 后可查到
    - 知识库管理页的 `indexedDocumentCount` 与文档列表 `status=INDEXED` 过滤结果一致

### 假设与默认值

- 默认页大小 `20`，上限 `100`，与现有调试接口的轻量规模一致。
- 第一版不做：全文搜索、批量操作、列自定义、导出、拖拽排序、多状态并选、列头点击排序。
- 第一版不做详情页，不扩展现有单文档接口返回结构来承载更丰富详情。
- 文档列表是 `ingest` 管理主入口，但上传页仍保留为独立导航入口。
- `kbId` 过滤传入不存在的值时返回空列表，不视为客户端错误——因为该 `kbId` 可能曾经存在但已被停用（知识库 `INACTIVE` 场景）。
- 本主题依赖知识库主数据化成果，开发前需确保知识库分支已合并到 `feature/v1-1-closure`。

## 1. 一句话结论

账号生命周期后端已完成首期治理闭环。

当前系统已经不再只有“登录 + bootstrap admin + 成员角色调整”，

## 2. 已完成能力

### 2.1 账号治理接口

已完成以下接口：

- `GET /api/v1/admin/accounts`
- `POST /api/v1/admin/accounts`
- `PATCH /api/v1/admin/accounts/{userId}/status`
- `POST /api/v1/admin/accounts/{userId}/password/reset`
- `DELETE /api/v1/admin/accounts/{userId}/membership`

### 2.2 账号治理动作

已支持：

- 查询工作区账号列表
- 创建本地账号
- 启用 / 停用账号
- 重置密码
- 移除成员关系

### 2.3 审计落地

以下动作已纳入 `audit_events`：

- `MANAGED_ACCOUNT_CREATED`
- `MANAGED_ACCOUNT_STATUS_UPDATED`
- `MANAGED_ACCOUNT_PASSWORD_RESET`
- `MANAGED_ACCOUNT_MEMBERSHIP_REMOVED`

## 3. 关键实现边界

### 3.1 主数据未重做

本轮没有新增重复账号主数据表，而是直接复用：

- `users`
- `local_credentials`
- `workspace_memberships`
- `login_lock_states`

### 3.2 账号状态与成员状态分离

当前规则已明确分层：

- 账号启用 / 停用改 `users.status`
- 成员移除改 `workspace_memberships.status`

这避免了“身份状态”和“组织关系状态”混在一起。

### 3.3 密码重置语义已收口

管理员重置密码时，后端会同时：

- 更新密码哈希
- 清空失败计数
- 清空锁定截止时间

因此重置密码后账号可直接恢复登录，不会被历史锁定状态阻塞。

## 4. 与现有接口的关系

### 4.1 未破坏旧的成员治理接口

现有：

- `GET /api/v1/admin/members`
- `PATCH /api/v1/admin/members/{userId}/role`

仍保持原语义：

- 只关注“有效成员”
- 只处理成员角色治理

账号生命周期没有继续挤进 `members` 接口，而是单独落到 `accounts` 接口组。

### 4.2 认证与授权体系继续复用

账号治理接口继续复用现有基线：

- `Spring Security + HttpSession + HttpOnly Cookie`
- `AuthorizationService.requireCanManageWorkspace()`
- 统一 `401 / 403`
- 统一 CSRF Header 基线

## 4. 前端行为规则

问答页现在按以下规则解释 #10 后端响应：

1. `references.length > 0` 时展示引用卡片列表；否则展示无命中空态。
2. 每张引用卡片以 `sourceFilename` 作为主要来源标题，以 `documentId` 作为可复制的追溯标识。
3. `sourceVersionNumber` 以 `vN` 形式展示；字段缺失时降级为“未知版本”，避免旧响应导致页面崩溃。
4. `sourceUpdatedAt` 使用中文日期时间格式展示；字段缺失或格式异常时展示原值或“未知更新时间”。
5. `isLatestVersion === false` 时直接判定 stale；如果后端未返回该布尔值，则用 `sourceVersionNumber < latestVersionNumber` 兜底判断。
6. 顶部 stale 提示不根据 `staleReferences` 是否存在来展示，而是要求同时满足“本次回答有引用”和“后端明确声明存在 stale reference”，避免无引用兜底回答出现版本噪音。

## 5. 数据契约接入

前端 `qaApi` 已接入 #10 的扩展响应字段：

- `references[].sourceVersionNumber`：实际用于回答的 document version 号。
- `references[].sourceUpdatedAt`：实际用于回答的版本更新时间。
- `references[].isLatestVersion`：引用版本是否为当前最新版本。
- `references[].latestVersionNumber`：对应 document 当前最新版本号。
- `references[].sourceFilename`：实际用于回答的版本来源文件名。
- `staleReferences.hasStaleReferences`：是否存在非最新版本引用。
- `staleReferences.staleReferenceCount`：非最新版本引用条数。
- `staleReferences.staleDocumentCount`：涉及的 document 数。
- `staleReferences.documents[]`：stale document 明细，供后续扩展更细粒度提示。

这些字段在前端 schema 中按兼容方式接入：引用卡片字段允许缺失或为空，以保障旧数据和灰度响应不会让问答页直接不可用；`staleReferences` 使用 `nullish`，符合“无引用时不展示版本提示”的契约语义。

## 6. 联调问题与修复摘要

联调时发现问答检索会触发 `Not supported expression type: ISNULL`。根因是版本 1 兼容过滤中使用了 `builder.isNull(...)`，但 Spring AI 1.1.2 的 `PgVectorFilterExpressionConverter` 不支持 `ISNULL`。

修复后，问答检索过滤只生成 PGVector 支持的等值表达式：

- 新向量优先使用 `documentVersionNumber = N`。
- 版本化旧向量兼容 `splitVersion = version-{N}-v1`。
- 历史初始向量兼容 `splitVersion = v1`。
- 新增测试直接调用 `PgVectorFilterExpressionConverter.convertExpression(...)`，防止同类过滤表达式再次导致运行时 500。

该修复解除 #11 前端联调的实际阻塞：前端能稳定拿到 #10 契约中的版本化引用字段与 `staleReferences` 汇总。

该问题虽然发生在后端检索适配层，但它直接影响 #11 的验收：如果 PGVector 过滤表达式转换失败，问答页无法获得任何引用结果，也就无法验证版本字段和 stale 提示。因此 closure 中将它作为 #11 联调阻塞一并记录。

## 7. 可访问性与界面收口

- 控制台顶部新增“问答控制台”快捷入口，避免只依赖侧边栏菜单导致入口不明显。
- 引用卡片对长文件名和长 `documentId` 使用换行与复制能力，避免挤压版本标签。
- 引用卡片列表使用自适应网格，窄屏下自动切换为单列。
- stale reference 顶部提示使用 warning 语义，避免和普通引用数量标签混淆。
- 控制台 header 调整为左右分区布局，移动端切换为上下布局，避免入口按钮和账号区重叠。

# 版本正文 artifact storage port 后端基线收口说明

## 1. 收口范围

本文用于记录 GitHub issue #22《版本正文 artifact storage port 与 key resolver 后端基线》的完成情况。

本次收口覆盖版本级源文件与处理产物的本地存储路径规则、版本正文 artifact 存储端口、key resolver、artifact 缺失与最大读取大小边界，以及删除时源文件与处理产物的清理语义。不包含 #23、#24、#25 中规划的三个正文读取 REST endpoint。

## 3. 验收对照

- 应用层通过端口读写版本处理产物：`ProcessDocumentApplicationService` 通过 `DocumentProcessingArtifactStorage.saveVersion(...)` 按 `document.latestVersionNumber()` 落盘，后续正文读取可通过 `loadVersionArtifact(...)` 读取指定版本 artifact。
- artifact key 包含完整版本身份：`DocumentStorageKeyResolver.resolveArtifactKey(...)` 生成 `artifacts/{workspaceId}/documents/{documentId}/versions/{versionNumber}/{artifactName}`。
- source 与 artifacts prefix 隔离：源文件统一写入 `source/{workspaceId}/documents/{documentId}/versions/{versionNumber}/{filename}`；处理产物统一写入 `artifacts/{workspaceId}/documents/{documentId}/versions/{versionNumber}/...`。
- artifact 缺失是稳定业务分支：`loadVersionArtifact(...)` 在文件不存在或不是常规文件时返回 `Optional.empty()`，供 #23、#24、#25 映射为 `CONTENT_ARTIFACT_MISSING`。
- 缺失 artifact 不触发兜底生成：处理产物读取只读取 artifacts prefix，不读取 source prefix，不重新解析源文件，也不从 `vector_store` chunk 拼接正文。
- 最大读取大小边界已落地：`loadVersionArtifact(...)` 在文件字节数超过 `maxBytes` 时抛出 `DocumentVersionArtifactTooLargeException`，供上层映射为 `CONTENT_TOO_LARGE`。
- 源文件读取已收紧为新路径：开发阶段不再保留迁移前 `data/ingest/{documentId}` 旧路径回退，源文件缺失会直接返回空，由处理链路暴露为源文件缺失。
- 删除清理保持 prefix 隔离：删除 document 时清理 `source/.../{documentId}` 与 `artifacts/.../{documentId}`，不会把源文件和处理产物混在同一目录规则中处理。

## 4. 关闭判断

#22 可以关闭。

判断依据如下：

- #22 的范围是后端存储基线，不要求开放正文读取 REST endpoint；endpoint 留给 #23、#24、#25。
- 当前实现已经建立 `DocumentProcessingArtifactStorage` 端口和本地 adapter，后续应用层无需感知本地路径或对象存储 SDK。
- key resolver 已统一表达 source 与 artifacts 两类逻辑 key，符合 `ADR-0006` 对版本级 source/artifact 隔离的决策。
- 处理链路已按 latest version 写入 `cleaned.md`，不会继续写入 document 级共享正文产物。
- 测试已经覆盖 key 规则、prefix 隔离、artifact 缺失、最大读取大小、源文件版本隔离和删除清理行为。

```markdown

## Closure Summary

#22 已完成，可以按 completed 关闭。

### 范围确认

本 issue 只交付版本正文读取的后端存储基线，不包含正文读取 REST endpoint。`GET /api/v1/documents/{documentId}/content`、`GET /api/v1/documents/{documentId}/askable-content` 和 `GET /api/v1/documents/{documentId}/versions/{versionNumber}/content` 分别由 #23、#24、#25 承接。

### 已完成内容与验收对照

- 建立 `DocumentProcessingArtifactStorage` 端口，支持按 `workspaceId + documentId + versionNumber + artifactName` 保存与读取版本处理产物。
- 新增 `DocumentStorageKeyResolver`，统一生成 source 与 artifacts 两类逻辑 key。
- `cleaned.md` 写入路径收敛为 `artifacts/{workspaceId}/documents/{documentId}/versions/{versionNumber}/cleaned.md`。
- 源文件写入路径收敛为 `source/{workspaceId}/documents/{documentId}/versions/{versionNumber}/{filename}`。
- artifact 缺失返回稳定空分支，不触发源文件重解析，也不从 vector_store chunk 拼接正文。
- artifact 超过读取上限时抛出稳定异常，供后续 endpoint 映射 `CONTENT_TOO_LARGE`。
- 删除 document 时分别清理 source prefix 与 artifacts prefix 下的版本文件。
- 开发阶段已移除迁移前旧路径读取回退：源文件读取只认 source prefix 下的版本路径，缺失时直接返回空，避免把旧 document 级源文件误当作某个 document version 的源文件。

### 关键实现落点

- `DocumentProcessingArtifactStorage`：定义 `saveVersion(...)` 与 `loadVersionArtifact(...)`，应用层后续通过这个端口读取版本处理产物，不直接依赖本地路径或对象存储 SDK。
- `DocumentVersionArtifactContent`：承载 artifact 逻辑 key、正文内容和字节长度，供上层接口组装正文响应。
- `DocumentVersionArtifactTooLargeException`：区分“产物存在但超过读取上限”的稳定分支，后续映射为 `CONTENT_TOO_LARGE`。
- `DocumentStorageKeyResolver`：集中生成 `source/...` 与 `artifacts/...` key，确保 `workspaceId`、`documentId`、`versionNumber` 和 artifact/source 名称都进入路径身份。
- `LocalDocumentProcessingArtifactStorage`：只从 artifacts prefix 读取处理产物；缺失时返回 empty，不读取 source、不重新解析、不拼接 chunk。
- `LocalDocumentSourceStorage`：只从 source prefix 的版本路径读取源文件，不再读取 `data/ingest/{documentId}` 旧路径。
- `ProcessDocumentApplicationService`：处理链路按 `document.latestVersionNumber()` 调用 `saveVersion(...)`，确保 `cleaned.md` 归属 document version。
- `DeleteDocumentApplicationService`：删除 document 时同时清理 source prefix 和 artifacts prefix 下的物理文件。

### 架构边界

- `cleaned.md` 当前已经是 version-level artifact，不是 document-level 共享文件。
- source file 与 artifact file 使用不同 prefix，逻辑隔离，后续迁移到 MinIO 时可复用同一 key 规则。
- artifact 缺失不会被“智能兜底”隐藏；上层接口应显式映射为 `CONTENT_ARTIFACT_MISSING`。
- 正文过大不会静默截断；上层接口应显式映射为 `CONTENT_TOO_LARGE`。
- #22 不引入源文件下载、源文件实时解析或从 `vector_store` chunk 拼接完整正文的路径。

- `git diff --check` 通过。

测试覆盖内容包括：

- source key 与 artifact key 使用隔离 prefix。
- 版本处理产物写入 artifacts prefix，且不写入 source prefix。
- artifact 缺失时返回 empty，即使 source prefix 下存在同名文件也不会读取。
- artifact 超过 `maxBytes` 时抛出稳定异常。
- 删除 artifact 时只清理 artifacts prefix，不影响 source prefix。
- 源文件读取只命中新 source 版本路径，不回退到 document 级旧路径。
- 处理链路按 latest version 写入版本处理产物。
- 删除链路会调用 source storage 与 artifact storage 两类清理。
```

## 7. 审阅建议

建议按以下顺序审阅：

1. 先看 `DocumentStorageKeyResolver`，确认 source 与 artifacts key 均包含 `workspaceId`、`documentId` 和 `versionNumber`。
2. 再看 `DocumentProcessingArtifactStorage` 与 `LocalDocumentProcessingArtifactStorage`，确认 `loadVersionArtifact(...)` 的缺失和过大分支没有兜底读取源文件。
3. 检查 `LocalDocumentSourceStorage`，确认源文件读取只认 `source/{workspaceId}/documents/{documentId}/versions/{versionNumber}` 新路径。
4. 检查 `ProcessDocumentApplicationService`，确认处理成功后按 latest version 写入 `cleaned.md`。
5. 检查 `DeleteDocumentApplicationService`，确认删除时同时清理 source 与 artifacts 两类存储。
6. 最后运行上方测试命令，确认 #22 的后端存储基线没有回退。

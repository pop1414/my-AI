# 统一正文接口 source=ASKABLE_BASELINE 后端契约收口说明

## 1. 收口范围

本文用于记录 GitHub issue #24《统一正文接口 source=ASKABLE_BASELINE 后端契约》的完成情况。

本次收口覆盖 `GET /api/v1/documents/{documentId}/content?source=ASKABLE_BASELINE` 的后端端到端能力，包括 askable baseline 版本选择、普通读者正文读取权限、正文 artifact 读取、状态分支、统一响应字段、OpenAPI/ADR 对齐和测试闭环。不包含 `source=EXPLICIT_VERSION` 历史版本读取，也不包含前端 QA 引用侧栏接入。

## 3. 验收对照

- endpoint 已支持 `source=ASKABLE_BASELINE`：`DocumentIngestController#getContent(...)` 统一接收 `LATEST|ASKABLE_BASELINE` 并映射到应用层来源枚举。
- 成功响应字段已齐备：`DocumentContentResponse` 包含 `documentId`、`versionNumber`、`latestVersionNumber`、`isLatestVersion`、`isAskableVersion`、`source`、`status`、`filename`、`createdAt`、`updatedAt`、`contentMarkdown`、`contentLength`、`truncated`。
- latest `INDEXED` 时可返回同一 latest 版本但读取意图不同：应用层对 `ASKABLE_BASELINE` 使用 `findLatestIndexedVersionNumber(...)` 选择版本；当 latest 本身已 `INDEXED` 时，返回同一版本但 `source = ASKABLE_BASELINE`。
- latest `INGESTING` 且旧版本 `INDEXED` 时返回旧 indexed baseline：应用层只读取最近一个 indexed 版本，不读取 latest `INGESTING` 版本的 artifact。
- latest `FAILED with cleaned.md` 时返回最近 indexed baseline：`ASKABLE_BASELINE` 分支优先使用问答基线版本，不回落到 failed latest 正文。
- 当前没有可问答版本时返回 `409 + CONTENT_NOT_READY`：`findLatestIndexedVersionNumber(...)` 返回 0 时，应用层直接映射未就绪，不读取 artifact。
- askable baseline 正文尚未生成时返回 `409 + CONTENT_NOT_READY`：对 `ASKABLE_BASELINE` 分支，artifact 缺失统一映射为未就绪，而不是 `CONTENT_ARTIFACT_MISSING`。
- 普通 `KB_READER` 可读取 askable baseline 正文：`AuthorizationService.requireCanReadDocument(...)` 回退到知识库级 `KB_READER` 及以上角色进行读取授权。
- 普通读者不会因此获得历史版本浏览能力：本次查询对象只接受 `documentId + source`，不接受显式 `versionNumber`；`ASKABLE_BASELINE` 只能由服务端选择当前问答基线。
- `KB_ASKER` 兼容边界已明确：`KB_ASKER` 仍可用于问答，但不能读取 askable baseline 正文。
- 读取 askable baseline 不改变后续 QA baseline：应用服务只调用 `findById(...)`、`findLatestIndexedVersionNumber(...)`、`findVersionByNumber(...)` 和 artifact 读取；测试显式验证不会再读取 latest 版本事实，也没有任何写路径。
- OpenAPI 与 ADR 已对齐：`docs/04-api-contract.yaml` 和 `ADR-0006` 已同步表达 `ASKABLE_BASELINE` 语义。

## 4. 关闭判断

#24 可以关闭。

判断依据如下：

- issue 目标是补齐统一正文接口 `source=ASKABLE_BASELINE` 的后端契约，而当前 controller、application service、authorization 和 OpenAPI 都已覆盖这条语义。
- askable baseline 的核心分支已经齐备：latest 已 indexed、latest ingesting 回退旧 indexed、latest failed 保持旧 indexed、无基线版本/正文未生成返回 `CONTENT_NOT_READY`。
- 普通读者读取权限与 `KB_ASKER` 拒绝边界已通过授权测试固定下来。
- 读取路径是只读的，不会改写问答基线，也不允许调用方借此浏览任意历史版本。

## 7. 审阅建议

建议按以下顺序审阅：

1. 先看 `DocumentContentSource`、`GetDocumentContentQuery` 与 `GetDocumentContentUseCase`，确认 askable baseline 语义没有暴露显式版本号输入。
2. 再看 `GetDocumentContentApplicationService`，确认版本选择、未就绪分支和只读行为都在应用层完成。
3. 检查 `AuthorizationService` 与对应测试，确认 `KB_READER` 允许、`KB_ASKER` 拒绝的权限边界准确。
4. 最后运行上方测试命令，确认 askable baseline 读取闭环没有回退。

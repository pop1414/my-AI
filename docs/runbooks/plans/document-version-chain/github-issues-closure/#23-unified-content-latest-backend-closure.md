# 统一正文接口 source=LATEST 后端契约收口说明

## 1. 收口范围

本文用于记录 GitHub issue #23《统一正文接口 source=LATEST 后端契约》的完成情况。

本次收口覆盖 `GET /api/v1/documents/{documentId}/content?source=LATEST` 的后端端到端能力，包括 latest 版本选择、正文 artifact 读取、状态分支、权限校验、错误码映射、REST 响应字段和测试闭环。不包含 `source=ASKABLE_BASELINE`、`source=EXPLICIT_VERSION` 两个分支，也不包含前端页面接入。

- latest 正文读取用例：`src/main/java/io/github/spike/myai/ingest/application/usecase/GetDocumentContentUseCase.java`
- latest 正文读取查询对象：`src/main/java/io/github/spike/myai/ingest/application/query/GetDocumentContentQuery.java`
- latest 正文读取结果：`src/main/java/io/github/spike/myai/ingest/application/result/DocumentContentResult.java`
- latest 正文读取应用服务：`src/main/java/io/github/spike/myai/ingest/application/service/GetDocumentContentApplicationService.java`
- REST controller 入口：`src/main/java/io/github/spike/myai/ingest/interfaces/rest/DocumentIngestController.java`
- REST 响应 DTO：`src/main/java/io/github/spike/myai/ingest/interfaces/rest/dto/DocumentContentResponse.java`

## 3. 验收对照

- endpoint 已落到统一路径：`DocumentIngestController#getContent(...)` 暴露 `GET /api/v1/documents/{documentId}/content`，并要求 `source=LATEST`。
- 成功响应字段已齐备：`DocumentContentResponse` 包含 `documentId`、`versionNumber`、`latestVersionNumber`、`isLatestVersion`、`isAskableVersion`、`source`、`status`、`filename`、`createdAt`、`updatedAt`、`contentMarkdown`、`contentLength`、`truncated`。
- latest `INDEXED` 时返回 latest 正文：应用服务固定按 document 的 `latestVersionNumber` 读取版本 fact 和 `cleaned.md`，成功时返回 `source = LATEST`。
- latest `INGESTING` 且无 `cleaned.md` 时返回 `409 + CONTENT_NOT_READY`：`missingContent(...)` 对 `UPLOADED`、`INGESTING` 分支统一映射为未就绪，不回退旧版本。
- latest `FAILED` 且已有 `cleaned.md` 时允许返回 failed latest 正文：应用服务直接读取 latest version 的 artifact，不因状态为 `FAILED` 而拦截。
- latest 版本选择由服务端控制：`GetDocumentContentQuery` 只接受 `documentId`，不接受 `versionNumber`，调用方不能模拟 latest。
- `DELETED` document 拒绝正文读取：应用服务在读 artifact 前把 `DELETED` 映射为 `404 + DOCUMENT_NOT_FOUND`。
- 正文过大返回 `413 + CONTENT_TOO_LARGE`：artifact storage 抛出 `DocumentVersionArtifactTooLargeException` 后，由应用服务稳定映射。
- artifact 缺失返回 `500 + CONTENT_ARTIFACT_MISSING`：latest 终态版本缺失 `cleaned.md` 时返回稳定错误码，不静默截断，也不兜底重建。
- 权限边界已接入：应用服务通过 `AuthorizationService.requireCanReadDocument(...)` 校验正文读取权限，拒绝时返回 `403 + DOCUMENT_CONTENT_FORBIDDEN`。
- 应用层与 REST 层测试已覆盖成功路径、状态分支、错误码和权限边界。

## 4. 关闭判断

#23 可以关闭。

判断依据如下：

- issue 目标是打通 `source=LATEST` 后端闭环，而当前代码已经具备从 controller 到 application service 再到 artifact storage 的完整读取链路。
- latest 语义已经收紧为“只读当前 latest version”，不会回退旧版本，也不允许调用方通过参数指定版本。
- `INGESTING`、`FAILED`、`DELETED`、artifact 缺失、正文过大和权限拒绝等关键分支均已有稳定业务行为与测试。
- 响应 DTO 已收敛为统一正文接口所需结构，后续 #24、#25 可在此结构上继续补齐其他 `source` 语义。

# RAG 权限体系 — 前端接入实施计划

日期：2026-05-10  
状态：Draft  
来源分支：`feature/auth-authorization-governance`  
建议前端分支：`feature/auth-frontend`

## 1. 背景

后端权限模块已完成三大分支建设：

1. `feature/auth-flyway-schema` — Flyway schema 接管、`workspace_id` 显式化、grant/audit 表落地
2. `feature/auth-security-baseline` — Spring Security、Session + Cookie 登录、CSRF Header、登录锁定、bootstrap admin、CurrentUserProvider、AuthorizationService、业务权限接入
3. `feature/auth-authorization-governance` — 成员管理、知识库授权、文档授权、审计查询四类治理接口

后端 API 契约已稳定，满足前端接入条件。前端接入仍分两阶段推进：先建认证基础设施，再建治理页面。本计划在原方案基础上补齐以下落地风险：

- 避免请求层全局 `401` 跳转误伤登录接口和登录态恢复接口
- 避免登录态恢复与路由守卫首帧竞争，导致已登录用户刷新后误跳登录页
- 修正文档中的角色/权限枚举值，严格对齐 `docs/api/openapi.yaml`
- 补齐管理页路由、菜单、标题、入口与跳转路径的闭环定义

## 3. 阶段一：认证基础设施

### 3.1 请求层基础改造

**文件**：`web/src/shared/api/request.ts`（修改）

- 所有请求统一补齐 `credentials: 'include'`，确保 Session Cookie 能稳定随请求发送
- 所有非 `GET` / `HEAD` / `OPTIONS` 请求自动添加 `X-MYAI-CSRF: 1` Header
- 保留现有 `ApiError` 类与错误抛出逻辑
- `requestJson` 新增可选参数：`options?: { authPolicy?: 'redirect-on-401' | 'ignore-401' }`
- 默认策略为 `redirect-on-401`
- 仅当满足以下条件时才执行 `401` 跳转：
  - `authPolicy === 'redirect-on-401'`
  - 当前路径不在 `/login`
- 跳转目标固定为 `/login?redirect=当前路径`，其中 `redirect` 保存 `pathname + search`

### 3.2 Auth API 模块

**文件**：`web/src/shared/api/authApi.ts`（新建）

Zod schema 定义严格对齐 `docs/api/openapi.yaml`：

- `LoginRequest`
- `LoginResponse`
- `CurrentUserResponse`

函数定义：

- `login(username, password)` → `POST /api/v1/auth/login`
- `logout()` → `POST /api/v1/auth/logout`
- `getCurrentUser()` → `GET /api/v1/auth/me`

约束：

- `login()` 使用 `authPolicy: 'ignore-401'`
- `logout()` 使用 `authPolicy: 'ignore-401'`
- `getCurrentUser()` 使用 `authPolicy: 'ignore-401'`
- `LoginResponse` 按契约解析 `user` 字段，不将整个响应对象误当作当前用户对象

### 3.3 AuthContext 当前用户上下文

**文件**：`web/src/shared/auth/AuthContext.tsx`（新建）

上下文不再只承载 `CurrentUser | null`，而是承载三态认证模型：

- `status: 'loading' | 'authenticated' | 'anonymous'`
- `user: CurrentUser | null`
- `isAuthenticated`
- `isAdmin`
- `login(username, password)`
- `logout()`

`AuthProvider` 规则：

- 挂载时调用 `getCurrentUser()` 恢复登录态
- `getCurrentUser()` 成功：
  - `status = 'authenticated'`
  - `user = 当前用户`
- `getCurrentUser()` 返回 `401`：
  - `status = 'anonymous'`
  - `user = null`
- `getCurrentUser()` 返回其他错误：
  - 默认也进入 `anonymous`
  - 通过页面级错误提示保留排障信息，不阻塞页面渲染
- `login(username, password)`：
  - 调用登录接口
  - 成功后设置 `authenticated`
  - 写入当前用户上下文
- `logout()`：
  - 调用登出接口
  - 后端返回 `204` 或 `401` 都视为前端可安全完成登出
  - 清空当前用户上下文
  - 跳转 `/login`

管理员判定规则固定为：

- `workspaceRole === 'WORKSPACE_OWNER'`
- 或 `workspaceRole === 'WORKSPACE_ADMIN'`

### 3.4 路由守卫

**文件**：`web/src/shared/auth/RouteGuards.tsx`（新建）

- `ProtectedRoute`
  - `status === 'loading'` → 渲染全屏 `Spin`
  - `status === 'anonymous'` → `<Navigate to="/login?redirect=当前路径" replace />`
  - `status === 'authenticated'` → `<Outlet />`
- `AdminRoute`
  - 先复用 `ProtectedRoute` 的认证判断
  - 已登录但非管理员 → 渲染 Ant Design `<Result status="403">`
  - 不做静默重定向

### 3.5 登录页面

**文件**：`web/src/features/auth/pages/LoginPage.tsx`（新建）

- 独立全屏布局，不使用 `ConsoleLayout`
- 居中卡片：品牌标识 + 用户名/密码表单 + 登录按钮
- Ant Design `Form` + `useMutation`
- 登录成功跳转规则：
  - 优先跳转 `redirect` query param
  - 无 `redirect` 时跳转 `/ingest/documents`
- 已登录用户访问 `/login`：
  - 自动跳转 `redirect` 或 `/ingest/documents`
- 登录失败：
  - 留在当前登录页
  - 展示后端错误信息
  - 不触发整页跳转

### 3.6 路由集成

**文件**：`web/src/app/AppRoutes.tsx`（修改）

路由结构固定为：

```tsx
<Routes>
  <Route path="/login" element={<LoginPage />} />

  <Route element={<ProtectedRoute />}>
    <Route path="/" element={<ConsoleLayout />}>
      <Route index element={<Navigate to="/ingest/documents" replace />} />

      {/* 现有业务路由 */}
      {/* ... */}

      <Route element={<AdminRoute />}>
        <Route path="/admin/members" element={<MembersPage />} />
        <Route path="/admin/audit-events" element={<AuditEventsPage />} />
        <Route
          path="/admin/knowledge-bases/:kbId/grants"
          element={<KnowledgeBaseGrantsPage />}
        />
        <Route
          path="/admin/documents/:documentId/grants"
          element={<DocumentGrantsPage />}
        />
      </Route>
    </Route>
  </Route>
</Routes>
```

要求：

- `/login` 不进入控制台布局
- 所有业务页统一进入 `ProtectedRoute`
- 所有治理页统一进入 `AdminRoute`
- 根路由默认落到 `/ingest/documents`

### 3.7 Provider 注入

**文件**：`web/src/main.tsx`（修改）

Provider 顺序固定为：

`QueryClientProvider` → `BrowserRouter` → `AuthProvider` → `AppRoutes`

说明：

- `AuthProvider` 必须位于路由树内，便于安全读取当前地址并拼接 `redirect`
- 不再采用“`BrowserRouter` 外包裹 `AuthProvider`”的旧方案

### 3.8 Header 用户菜单

**文件**：`web/src/app/ConsoleLayout.tsx`（修改）

Header 右侧新增用户区域：

- 显示 `displayName`
- 显示工作区角色 Tag
- 下拉菜单包含：
  - 当前用户信息摘要
  - 退出登录

## 8. 验证方式

1. **Cookie 与 CSRF**：DevTools Network 确认写请求携带 `X-MYAI-CSRF: 1`，认证请求带上 Cookie
2. **登录页直出**：未登录访问 `/login`，页面可直接打开，不发生跳转循环
3. **登录失败**：输入错误账号密码后仍停留在 `/login`，表单展示错误信息
4. **登录成功**：登录后跳转 `redirect` 或 `/ingest/documents`，Header 显示用户名与角色
5. **刷新恢复**：已登录用户刷新任意受保护页面，停留原页面，不闪回登录页
6. **登出流程**：点击 Header 登出后跳回 `/login`，再次访问受保护页面需重新登录
7. **会话过期**：Session 过期后访问任意受保护业务 API，自动跳 `/login?redirect=原路径`
8. **403 处理**：已登录 MEMBER 访问 `/admin/members`，显示 403 提示页
9. **管理员可见性**：OWNER / ADMIN 可见系统管理分组与授权管理按钮；MEMBER 不可见
10. **治理接口**：逐项验证成员角色修改、知识库授权、文档授权、审计查询与分页
11. **枚举对齐**：所有前端 Select、Tag、请求体、响应解析均使用 OpenAPI 契约中的真实枚举值
12. **回归验证**：现有知识库、文档上传、状态查询、分块预览、重处理、删除、问答页面在登录后正常可用

## 9. 关键设计决策

- **401 跳转策略**：请求层保留统一处理能力，但通过 `authPolicy` 避免误伤 `/auth/login`、`/auth/me`、`/auth/logout`
- **登录态恢复**：`AuthProvider` 挂载后主动调 `GET /api/v1/auth/me`，并使用三态认证模型避免首帧误判
- **Provider 顺序**：`AuthProvider` 放到 `BrowserRouter` 内，保证后续使用路由上下文时不受限
- **治理页面入口**：知识库/文档授权管理从资源列表页进入，保持资源上下文一致
- **AdminRoute 403**：非管理员访问治理页时显示 `403 Result`，不做静默重定向
- **审计过滤器策略**：开放字符串字段优先用 `Input`，避免前端写死后端尚可能扩展的事件类型集合

## 10. 排除范围

- 不实现用户新建/邀请页面
- 不实现成员停用/移除页面
- 不实现管理员手动解锁页面
- 不实现多工作区切换
- 不实现批量授权、导入导出、远程搜索型成员选择器
- 不修改现有页面核心业务逻辑，仅补认证基础设施、治理入口与治理页面

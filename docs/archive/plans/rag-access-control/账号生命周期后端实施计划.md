# RAG 权限体系 - 账号生命周期后端实施计划

日期：2026-05-11  
状态：Completed  
主题归属：`rag-access-control` 专项  
范围边界：后端优先，仅补账号治理链路，不进入前端页面编码

## 1. 背景

在认证、安全基线、成员治理、知识库授权、文档授权、审计查询完成后，
权限专项仍存在一个明显缺口：

- 已有登录
- 已有 bootstrap admin
- 已有成员角色调整
- 但账号生命周期尚未形成完整治理闭环

具体表现为：

1. 缺少工作区账号列表视图
2. 缺少新增本地账号能力
3. 缺少账号启用 / 停用能力
4. 缺少密码重置能力
5. 缺少成员移除能力

这会导致权限治理只能“调角色、配授权”，但不能完成最基本的账号运营。

## 2. 本轮目标

本轮只补齐后端账号生命周期治理能力，保持以下原则：

- 不重做现有主数据模型
- 不破坏既有 `members` 接口语义
- 不提前编码前端后台页面
- 所有治理动作继续纳入现有认证、授权、审计体系

## 3. 范围边界

### 3.1 本轮要完成的能力

- 工作区账号列表查询
- 本地账号创建
- 账号启用 / 停用
- 密码重置
- 成员移除
- 上述操作对应的审计事件落库

### 3.2 本轮明确不做的能力

- 前端账号管理页面
- 邮件邀请、注册激活、找回密码
- 账号删除
- 多工作区账号迁移
- OIDC / SSO / API Token

## 4. 技术策略

### 4.1 主数据复用

直接复用现有 4 张表，不新增重复主数据：

- `users`
- `local_credentials`
- `workspace_memberships`
- `login_lock_states`

设计意图：

- `users.status` 负责账号启用 / 停用
- `workspace_memberships.status` 负责成员关系启用 / 移除
- `local_credentials` 负责密码凭证
- `login_lock_states` 负责失败次数与锁定状态

### 4.2 接口分层策略

不把账号生命周期继续塞进现有 `members` 接口。

原因：

- `members` 当前语义是“有效成员列表 + 角色调整”
- 账号生命周期涉及用户状态、密码、锁定状态，语义明显更宽

因此单独新增治理接口组：

- `GET /api/v1/admin/accounts`
- `POST /api/v1/admin/accounts`
- `PATCH /api/v1/admin/accounts/{userId}/status`
- `POST /api/v1/admin/accounts/{userId}/password/reset`
- `DELETE /api/v1/admin/accounts/{userId}/membership`

### 4.3 授权策略

统一复用：

- `AuthorizationService.requireCanManageWorkspace()`

即只有：

- `WORKSPACE_OWNER`
- `WORKSPACE_ADMIN`

可执行账号治理操作。

### 4.4 审计策略

本轮新增治理动作全部写入 `audit_events`：

- `MANAGED_ACCOUNT_CREATED`
- `MANAGED_ACCOUNT_STATUS_UPDATED`
- `MANAGED_ACCOUNT_PASSWORD_RESET`
- `MANAGED_ACCOUNT_MEMBERSHIP_REMOVED`

## 5. 实施拆解

### 5.1 模型与端口

新增：

- `ManagedAccount` 读模型
- `ManagedAccountRepository` 端口
- 账号治理相关命令 / 结果 / 异常 / 用例接口

### 5.2 应用服务

新增 5 个应用服务：

- `ListManagedAccountsApplicationService`
- `CreateManagedAccountApplicationService`
- `UpdateManagedAccountStatusApplicationService`
- `ResetManagedAccountPasswordApplicationService`
- `RemoveManagedAccountMembershipApplicationService`

### 5.3 基础设施

新增：

- `JdbcManagedAccountRepository`

实现职责：

- 聚合账号查询
- 新建用户、密码凭证、成员关系
- 更新用户状态
- 重置密码并清空锁定状态
- 将成员关系改为 `INACTIVE`

### 5.4 接口层

新增：

- `AccountAdminController`
- 对应 request / response DTO

错误语义约束：

- `400`：请求体为空或参数非法
- `404`：目标账号不存在
- `409`：用户名冲突

## 6. 关键规则

### 6.1 账号停用

账号停用只修改：

- `users.status`

不直接改：

- `workspace_memberships.status`

原因：

- 停用账号是身份层动作
- 成员移除是组织关系层动作
- 两者必须分离

### 6.2 成员移除

成员移除只修改：

- `workspace_memberships.status = INACTIVE`

不删除用户，不删除凭证。

### 6.3 密码重置

密码重置同时完成：

- 更新 `local_credentials.password_hash`
- 重置 `login_lock_states.failed_login_count = 0`
- 清空 `login_lock_states.locked_until`

这是为了避免管理员重置密码后，账号仍被历史锁定状态阻塞。

## 7. 验收标准

本轮完成时，至少满足：

1. 管理员可查询当前工作区账号列表
2. 管理员可创建本地账号并建立成员关系
3. 管理员可启用 / 停用账号
4. 管理员可重置账号密码并解除锁定状态
5. 管理员可移除成员关系
6. 上述操作全部写入审计日志
7. 现有 `members` 接口语义不被破坏

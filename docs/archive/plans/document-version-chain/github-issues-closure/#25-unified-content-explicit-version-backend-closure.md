# 统一正文接口 source=EXPLICIT_VERSION 权限与错误映射收口说明

## 1. 收口范围

本文用于记录 GitHub issue #25《统一正文接口 source=EXPLICIT_VERSION 权限与错误映射》的完成情况。

本次收口覆盖 `GET /api/v1/documents/{documentId}/content?source=EXPLICIT_VERSION&versionNumber={versionNumber}` 的后端端到端能力，包括显式历史版本选择、管理权限校验、错误码映射、统一响应字段、OpenAPI/ADR 对齐和测试闭环。不包含前端历史版本正文视图接入。

## 3. 验收对照

- endpoint 已支持 `source=EXPLICIT_VERSION`：`DocumentIngestController#getContent(...)` 统一接收 `LATEST|ASKABLE_BASELINE|EXPLICIT_VERSION`，并在 `EXPLICIT_VERSION` 分支透传 `versionNumber`。
- `source=EXPLICIT_VERSION` 成功响应字段已齐备：`DocumentContentResponse` 包含 `documentId`、`versionNumber`、`latestVersionNumber`、`isLatestVersion`、`isAskableVersion`、`source`、`status`、`filename`、`createdAt`、`updatedAt`、`contentMarkdown`、`contentLength`、`truncated`，其中 `source = EXPLICIT_VERSION`。
- `source=EXPLICIT_VERSION` 缺少 `versionNumber` 时返回 `400`：controller 在进入用例前直接拦截缺失参数。
- `source=EXPLICIT_VERSION` 的 `versionNumber` 非正数时返回 `400`：controller 与查询对象都对正整数约束做了保护。
- 目标 document 不存在时返回 `404 + DOCUMENT_NOT_FOUND`：应用服务在任何来源下都先读取 document，并对缺失与 `DELETED` 走统一拒绝逻辑。
- 目标 version 不存在时返回 `404 + VERSION_NOT_FOUND`：显式版本读取通过 `findExplicitVersionFact(...)` 对外暴露稳定版本不存在错误。
- 普通 `KB_READER` 访问任意显式历史版本正文时返回 `403 + VERSION_CONTENT_FORBIDDEN`：显式版本分支不复用 `requireCanReadDocument(...)`，而是收紧为 `requireCanManageDocument(...)`。
- `WORKSPACE_ADMIN`、`KB_MANAGER` 和 `DOC_ALLOW_MANAGE` 用户可读取指定历史版本正文：授权服务通过工作区级、文档级和知识库级三层规则为显式版本读取放行。
- `DOC_DENY` 会覆盖知识库管理角色回退：显式历史版本读取权限通过 `requireCanManageDocument(...)` 执行，`DOC_DENY` 仍拥有最高优先级。
- `DELETED` document 拒绝正文读取：应用服务在读取版本或 artifact 前即拒绝，不因用户具备管理权限而放行。
- 指定版本正文未就绪、产物缺失、正文过大时分别映射到 `CONTENT_NOT_READY`、`CONTENT_ARTIFACT_MISSING`、`CONTENT_TOO_LARGE`：处理中版本缺 artifact 走未就绪，终态缺 artifact 走产物缺失，超过服务端读取上限走过大错误。
- 读取历史版本不改变 QA baseline：应用服务对显式版本分支只执行读取类调用，不写 document，不推进 askable baseline，也不把历史版本切成新的默认问答基线。
- OpenAPI 与 ADR 已对齐：`docs/api/openapi.yaml` 与 `ADR-0006` 已同步表达 `source=EXPLICIT_VERSION&versionNumber={versionNumber}` 的权限和语义边界。

## 4. 关闭判断

#25 可以关闭。

判断依据如下：

- issue 目标是补齐统一正文接口 `source=EXPLICIT_VERSION` 的后端契约、历史版本权限和错误映射，而当前 controller、application service、authorization、OpenAPI 和 ADR 都已覆盖这条语义。
- `versionNumber` 校验、`VERSION_NOT_FOUND`、`VERSION_CONTENT_FORBIDDEN`、`CONTENT_NOT_READY`、`CONTENT_ARTIFACT_MISSING`、`CONTENT_TOO_LARGE` 等关键分支均已具备明确行为与测试。
- 历史版本读取权限已经收紧为“只有具备目标 document 管理权限的用户可读”，没有把普通读者的问答基线读取能力放大成历史正文浏览能力。
- 读取路径是只读的，不会改写问答基线，也不会把历史版本读取混成 latest 或 askable baseline 语义。

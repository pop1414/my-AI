# ADR-0005：RAG 权限体系基础决策

- 编号：ADR-0005
- 标题：RAG 权限体系基础决策
- 状态：Accepted
- 日期：2026-05-08

## 背景

当前系统已经完成：

- 知识库主数据化
- 文档列表与管理台
- 基于知识库的上传与问答主链路

但系统仍没有正式的认证与授权体系。  
如果继续沿用“轻量登录 + 入口封口”的思路，后续在知识库协作、文档可见范围、问答内容隔离和多工作区升级上都容易产生返工。

因此，需要先明确一组可长期沿用的权限基础决策。

## 备选方案
1. 延续轻量认证思路，只做单管理员访问保护
2. 先定成熟权限体系方向，再按阶段工程化落地
3. 直接按多租户 SaaS 权限平台一次性展开

## 决策

选择方案 2，并固定以下基础决策：

- 单工作区优先，但 `workspace` 必须先入模
- 本地账号优先，预留 OIDC / SSO 接口
- 服务端 Session 作为首期认证态
- 知识库级授权为主，文档级覆盖为补充
- `qa.ask` 只允许使用有权文档
- CSRF 采用 `SameSite + 自定义 Header`
- 登录暴力破解防护采用连续失败锁定

## 决策理由

- 单工作区优先可以控制首期复杂度，但 `workspace` 先入模可以避免未来从“全局空间”升级时大改主业务表
- 本地账号最适合当前工程阶段；预留 SSO 接口能避免后续身份层完全重做
- 服务端 Session 更适合当前内部协作型控制台，能减少首期 Token 设计负担
- 知识库是当前系统最稳定、最自然的业务隔离边界，因此应作为首期主授权资源
- 文档级覆盖可以处理少量例外，而无需一开始把全部授权下沉到文档粒度
- 对 RAG 系统来说，问答安全边界必须和可检索文档边界保持一致，否则会产生“回答内容越权但引用被裁剪”的风险
- `SameSite + 自定义 Header` 能和当前 SPA + Session 方案配合，作为首期清晰、可控的 CSRF 基线
- 本地账号直接暴露登录接口，必须有最基础的失败锁定机制，否则抗暴力破解能力不足

## 影响
### 正向影响
- 为后续工程化落地提供统一权限方向
- 把知识库、文档、问答三条主链路纳入同一套安全边界
- 降低未来升级到多工作区、SSO、机器身份时的结构性返工风险
- 让后续专题计划和接口接入不必再反复争论底层模型

### 负向影响 / 风险
- 首期需要引入安全框架与权限主数据，工程复杂度明显高于轻量登录
- 现有主业务表需要补 `workspace_id` 等扩展字段并回填历史数据
- 授权判断会进入文档列表、问答检索、文档管理等多条现有链路，联调面变大
- `SameSite` 策略未来可能受部署形态影响，需要保留配置弹性

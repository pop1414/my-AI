# UX Spec: 前端控制台

> 来源：CONTEXT.md §7.5（已迁出）
> 关联设计系统：`DESIGN.md`（Unified RAG Design System）

## 概述

前端控制台按"外层模块型导航 + 页面内任务型编排"组织，不是纯流程型站点，也不是纯资源 CRUD 台账。面向三类角色的三层体验：核对层、内容治理层、系统治理层，通过同一页面骨架、不同信息密度的方式展开。

## 已落地的稳定事实

- 一级导航已按 `文档 / 知识库 / 问答 / 系统管理` 四类模块收口
- 共享页面骨架固定为页头、摘要区、主工作区和状态区
- `knowledge` 页已作为真实接入路径验证共享骨架
- `loading / empty / error / ready` 已统一为共享状态卡表达
- 控制台外层已补齐 `skip link / nav / main` 可访问性骨架

## 角色体验分层

当前前端体验**不应**简化成"普通用户 / 管理员"二分，应至少区分三层：

| 层 | 角色 | 关注点 |
|----|------|--------|
| 核对层 | `KB_READER` | 问答、引用、问答基线正文与只读文档查看 |
| 内容治理层 | `KB_CONTRIBUTOR`、`KB_MANAGER` | 上传、版本、重处理、回退、删除与文档治理 |
| 系统治理层 | `WORKSPACE_ADMIN`、`WORKSPACE_OWNER` | 成员、账号、授权、审计与工作区级治理 |

## 页面主叙事

三类共享页面各自的核心叙事：

| 页面 | 主叙事 |
|------|--------|
| 问答页 | "我要问什么，系统基于什么回答，我如何核对依据" |
| 知识库页 | "我该进入哪个 `knowledge base` 开始问答或核对" |
| 文档详情页 | 普通成员："这份文档当前用于问答的依据是什么"；治理角色扩展："版本与治理动作" |

## 共享骨架原则

共享页面必须遵守"**同骨架、不同信息密度**"原则：

- 同一个页面骨架在不同角色下保持一致，不为不同角色维护两套割裂页面
- 管理者看到的是同一页面的更深一层，而不是在普通页面上零散粘贴一些额外按钮
- 角色差异优先通过信息展开层级、操作分区、入口深度和视角切换体现，而不是通过页面风格突变体现
- 管理能力应集中在页头操作区、治理侧栏或治理分区，不应散落在基础信息区、正文区或结果区各处

如果某个前端方案让管理者感觉自己正在使用"普通页面 + 额外补丁"，应视为体验边界退化。

## 视角切换规则

`document` 在前端心智上应拆成"**文档核对**"与"**文档治理**"两个视角，但它们不是新的领域对象：

- `文档核对`：面向 `KB_READER`，强调当前问答依据、当前状态、可核对内容与上下文
- `文档治理`：面向 `KB_CONTRIBUTOR`、`KB_MANAGER` 及更高治理角色，强调版本、重处理、删除、授权与审计相关动作
- 前端允许在同一 `document` 详情页内按权限展示不同深度，而不是复制两套详情页

### 视角默认落点

- 管理者从共享入口进入页面时，默认仍落在核对主叙事，而不是直接落在治理噪声最重的状态
- 管理者从治理入口进入页面时，可默认落在治理视角
- 文档详情页是显式视角切换的一等页面，应允许具备权限的用户在"核对视角 / 治理视角"之间切换
- 问答页可先采用隐式治理增强，不强制一开始提供显式治理视角切换
- 知识库页默认不提供显式视角切换，而是通过操作层级自然展开治理能力

## 导航与页面编排

- 一级导航保持模块型组织，当前主入口围绕 `文档`、`知识库`、`问答`、`系统管理` 稳定模块展开
- 页面内信息编排按任务型组织，优先让用户在当前页面内完成"进入、核对、继续下一步"的闭环
- 共享页面优先服务普通成员的主任务，再对更高权限角色自然展开更深的信息与治理能力
- 纯治理页面不伪装成普通页；成员、账号、授权、审计等页面直接按治理工作台设计

### 上传页交互规则

- 上传成功后前端默认跳转到文档详情页
- 上传页在未选择 `knowledge base` 时应阻止提交并提示先选择知识库
- 切换 `knowledge base` 后，上传页已选文件应自动清空
- 每次进入上传页都不预选 `knowledge base`，必须手动选择
- 上传页文件拖拽区应显示当前选中的 `knowledge base` 名称
- 未选择 `knowledge base` 时，上传页应展示空态提示，并保留可交互的知识库选择入口

### 文档列表与详情展示规则

- 文档列表页与详情页默认展示的文档名称应跟随最新版本的来源文件名更新
- 当前阶段不为 `document` 引入独立于来源文件名的稳定标题字段
- 从问答引用侧栏跳转到文档详情页时，应保留问答上下文；若当前问答基线不是最新版本，详情页应提示"从问答引用进入，当前问答基于 vN"

## 优先级排序

前端共享页面的优先级应始终遵守：

1. 先保证普通成员的核对路径顺畅
2. 再为内容治理角色增加版本与处理能力
3. 最后为系统治理角色增加跨资源治理能力

## 视觉与组件约束

所有前端界面设计、组件实现与视觉交互，必须严格遵循根目录下的 `DESIGN.md`（Unified RAG Design System）。关键约束：

- 禁止随意引入阴影
- 禁止使用非标准的配色方案
- 严格遵守 `JetBrains Mono` 作为代码和数据渲染字体
- 管理者面板采用 Supabase 风格高密度面板
- 普通用户问答/阅读流采用 Cursor 风格

# 接手文档质量回归清单

## 1. 目标

这份清单用于帮助新接手的人在不修改检索契约的前提下，先判断 `cleaned.md` 是否足够稳定。

如果基础文本已经出现标题漂移、段落断裂或结构块退化，后续无论采用普通分块还是父子分块，结果都会被坏输入放大。

## 2. 回归步骤

1. 先看 `cleaned.md` 是否仍保留标题、列表、表格和代码块。
2. 再看 `documents/chunks/preview` 是否沿着正确的语义边界切分。
3. 最后用固定问题做 `qa.ask` 回归，判断回答和引用是否落在预期正文位置。

## 3. 结构化检查表

- 标题层级
  - 一级标题不能和正文粘连
  - 二级标题不能被拍平成普通段落
- 段落边界
  - 同一自然段不要被错误拆成多段
  - 相邻段落不要因为换行修复被误拼接
- 结构块
  - 列表项顺序要保持稳定
  - 表格列不能被压成一行普通文本
  - 代码块围栏和缩进要保留

## 4. 指标对照

| 检查项 | 通过标准 | 常见失真 |
| --- | --- | --- |
| 标题层级稳定 | `h1/h2` 与正文边界清晰可见 | 标题丢失、标题和正文粘连 |
| 段落边界可信 | 自然段连续，长句不被幽灵换行打断 | 错误断段、错误拼接 |
| 结构块保真 | 列表、表格、代码块仍可直接阅读 | 列表拍平、表格退化、代码块错乱 |

## 5. 示例命令

```bash
curl -X GET "http://localhost:8080/api/v1/documents/{documentId}/chunks/preview?limit=5&previewChars=200"
```

上面的命令用于快速查看当前文档在向量化前的切分预览，确认 `sourceHint`、段落边界和结构块是否仍然可解释。

## 6. 额外说明

- 这份文档故意同时包含标题、列表、表格和代码块。
- 如果 parser 对原生 Markdown 仍做了过度重解析，最容易先坏掉的是表格和代码块。
- 如果 `cleaned.md` 看起来更整齐，但表格列顺序被破坏，也不能判定这轮优化成功。

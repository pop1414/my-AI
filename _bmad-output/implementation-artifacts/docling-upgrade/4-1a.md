# Story 4.1a: Epic 4 Phase 1 — 降级链删除 + null 校验

Status: review

## Story

As a 后端开发者，
I want 删除 DoclingDocumentParser 中的内容降级链并添加 null/空文件名防御性校验，
so that md_content 为空时直接报错（而非静默降级产生不确定行为），文件名非法时快速失败便于问题定位。

## Acceptance Criteria

1. `extractReaderMarkdown()` 中的内容降级链（html_content / text_content / doctags_content）已删除，仅保留 `md_content` 作为唯一内容源
2. `md_content` 为 null 或空白时抛出 `IllegalStateException`，错误消息包含 "md_content" 关键字
3. `parse()` 方法入口增加 null/空文件名校验，null 或空白 filename 抛出 `IllegalStateException`
4. 存量降级测试（`shouldFallbackToHtml`、`shouldFallbackToText`、`shouldFallbackToDoctags`）已移除或重写为报错断言
5. 新增测试覆盖 md_content 为空白字符串（非 null）的场景
6. 新增测试覆盖 null filename 和空字符串 filename 的场景
7. 编译通过：`mvn clean compile` 零错误
8. 存量测试通过：相关测试类零失败

## Dev Notes

### 背景

Epic 3 回顾（2026-06-18）识别出两项关键遗留工作：

- **D12**：`extractReaderMarkdown()` 存在内容降级链（md → html → text → doctags）。spike 决策：删除整个降级链，md_content 为空时直接报错。Phase 0 调查确认 md_content 空值频率为零，删除安全。
- **D11**：`parse()` 未校验 null/空文件名，可能导致 metadata 不一致。决策：防御性校验，顺手做。

配置化工作（HybridChunker maxTokens/mergePeers 从 IngestProperties 读取）已在之前的迭代中完成，不属于本次范围。

### 降级链删除详情

**文件：** `DoclingDocumentParser.java:255-295`（`extractReaderMarkdown()` 方法）

**当前实现：**
```java
if (document.getMarkdownContent() != null) {
    return document.getMarkdownContent();
}
if (document.getHtmlContent() != null) {
    log.info("降级使用 html_content");
    return document.getHtmlContent();
}
// ... text_content, doctags_content 同理
throw new IllegalStateException("... md/html/text/doctags all null");
```

**目标实现：**
```java
String mdContent = document.getMarkdownContent();
if (mdContent != null && !mdContent.isBlank()) {
    return mdContent;
}
throw new IllegalStateException(
    "docling response md_content is null/empty (status=%s)".formatted(status));
```

**关键点：**
- 不仅检查 null，还要检查 blank（空字符串、纯空白），对齐 D10 发现
- 错误消息必须包含 "md_content" 便于日志搜索
- 删除后 `extractReaderMarkdown()` 将只有 ~10 行有效代码

### null 文件名校验详情

**文件：** `DoclingDocumentParser.java:123`（`parse()` 方法入口）

**当前实现：** `filename` 传入后直接进入 `isMarkdownFilename()` 或 `callDoclingApi()`，null filename 会透传到 Docling API。

**目标实现：** 在 content 校验之后增加：
```java
if (filename == null || filename.isBlank()) {
    throw new IllegalStateException("filename must not be null or empty");
}
```

**调用链：** `ProcessDocumentApplicationService:143` → `documentTextParser.parse(document.filename(), sourceBytes)`。`document.filename()` 来自数据库，理论上不应为 null，但防御性校验遵循 fail-fast 原则。

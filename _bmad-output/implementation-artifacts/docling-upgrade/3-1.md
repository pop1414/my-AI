# Story 3.1: 重构 DocumentParserRouter

Status: review

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a 后端开发者，
I want 重构 DocumentParserRouter，将 TIKA 路由改为 DOCLING + REJECT，
So that 所有支持的格式走 Docling 路径，不支持的格式被快速拒绝并标记为永久失败。

## Acceptance Criteria

1. `DocumentParseRoute` 枚举替换为 `DOCLING` + `REJECT`，删除 `NATIVE_MARKDOWN`、`NATIVE_HTML`、`TIKA`。
2. `DocumentParserRouter.route()` 的 switch 使用 DOCLING 显式匹配全部 22 个支持的扩展名（pdf, doc, docx, xls, xlsx, ppt, pptx, png, jpg, jpeg, gif, bmp, tiff, tif, webp, md, markdown, mdown, mkd, html, htm, txt），default 分支抛出 `UnsupportedDocumentFormatException`。
3. 新建 `UnsupportedDocumentFormatException`（domain/model/ 下，继承 RuntimeException），构造器接收格式名，`getMessage()` 返回 `"不支持的文件格式: {format}"`。
4. `TikaDocumentTextParser.parse()` switch 更新：`case DOCLING` 委托 `DoclingDocumentParser`（与原 NATIVE_MARKDOWN/NATIVE_HTML 行为一致），`case REJECT` 抛出 `UnsupportedDocumentFormatException("unknown")`。
5. `DocumentParserRouter.fileExtension()` 方法签名和行为不变（`DoclingDocumentParser` 和 `ProcessingMetadataBuilder` 静态引用它，不在本 story 范围）。
6. null 文件名、空白文件名、无扩展名文件名、未知扩展名均被 `route()` 拒绝并抛出 `UnsupportedDocumentFormatException`。
7. `DocumentParserRouterTest` 全部重写：覆盖 8 种格式各至少一个代表性扩展名、REJECT 场景（csv/epub/rtf/unknown/null/blank）、`fileExtension()` 边界不变。
8. `TikaDocumentTextParser` switch 更新后编译通过。
9. `RetryPolicy` 无需修改 — `UnsupportedDocumentFormatException` 继承 `RuntimeException`，不匹配已知瞬时异常分类，默认归为永久错误（`RetryDecision(transientError=false)`）。
10. 编译通过：`mvn clean compile` 无错误。
11. 存量测试通过：`mvn "-Dtest=!MyAiApplicationTests" test` 无回归。

## Dev Notes

### 架构决策：路由返回枚举 vs 抛异常

**决策：** `route()` 方法对支持格式返回 `DOCLING`，对不支持格式抛出 `UnsupportedDocumentFormatException`（不是返回 `REJECT` 枚举）。

**理由：**
- Router 的核心职责是**格式分类**：支持 → 通行，不支持 → 拒绝
- 返回 REJECT 枚举要求每个调用方都添加 `case REJECT` 分支，增加认知负担
- 抛异常更符合 "invalid input → reject" 的语义契约
- `UnsupportedDocumentFormatException` 继承 `RuntimeException`，不匹配 RetryPolicy 的任何已知瞬时分类，默认归为永久错误 → `markFailed`，行为正确

**权衡：**
- ✅ 调用方无需修改（TikaDocumentTextParser 的 switch 不需要 REJECT case）
- ✅ 错误消息直接来自异常，保证可读性
- ⚠️ `route()` 方法名暗示"路由选择"，实际已变为"格式校验+路由"。Epic 3 清理后可重命名

### 路由映射表

| 扩展名 | 路由 | 格式族 |
|--------|------|--------|
| `pdf` | DOCLING | 文档 |
| `doc`, `docx` | DOCLING | 文档 |
| `xls`, `xlsx` | DOCLING | 电子表格 |
| `ppt`, `pptx` | DOCLING | 演示文稿 |
| `png`, `jpg`, `jpeg`, `gif`, `bmp`, `tiff`, `tif`, `webp` | DOCLING | 图片（OCR） |
| `md`, `markdown`, `mdown`, `mkd` | DOCLING | Markdown |
| `html`, `htm` | DOCLING | HTML |
| `txt` | DOCLING | 纯文本 |
| `csv`, `epub`, `rtf`, `json`, `xml`, `zip`, `rar`, `7z`, `tar`, `gz`, `mp3`, `mp4`, `wav`, `avi`, `mov`, 其他 | **拒绝** | 不支持 |

**总计：** 22 个支持扩展名，其余全部拒绝。

### UnsupportedDocumentFormatException 设计

**文件：** `src/main/java/io/github/spike/myai/ingest/domain/model/UnsupportedDocumentFormatException.java`

```java
/**
 * 不支持的文档格式异常。
 *
 * <p>当上传的文件格式不在系统支持范围内时抛出。
 * 属于永久性错误，不应重试。
 *
 * @author spike
 * @since 1.0.0
 */
public class UnsupportedDocumentFormatException extends RuntimeException {

    private final String format;

    public UnsupportedDocumentFormatException(String format) {
        super("不支持的文件格式: " + format);
        this.format = format;
    }

    public String format() {
        return format;
    }
}
```

**异常层次定位：** 与 `DoclingParseException` 体系并行，不混用：
- `DoclingParseException` → Docling API 调用失败
- `UnsupportedDocumentFormatException` → 格式不支持，在调用 Docling 之前拒绝

### RetryPolicy 集成分析

**文件：** `src/main/java/io/github/spike/myai/ingest/application/service/RetryPolicy.java`

`UnsupportedDocumentFormatException` 继承 `RuntimeException`，不匹配 RetryPolicy.classify() 的任何已知模式：
1. ~~HttpStatusCodeException~~ → 不匹配
2. ~~WebClientResponseException~~ → 不匹配
3. ~~TransientDataAccessException~~ → 不匹配
4. ~~SocketTimeoutException/ConnectException~~ → 不匹配
5. ~~IOException~~ → 不匹配
6. ~~DoclingPermanentException~~ → 不匹配（不同继承链）
7. ~~DoclingTransientException~~ → 不匹配
8. ~~IllegalArgumentException~~ → 不匹配（不是 IAE）

→ classify() 返回 null → decide() 返回 `RetryDecision(false, "UnsupportedDocumentFormatException", "不支持的文件格式: csv")` → **永久错误** → markFailed

**结论：** RetryPolicy 无需修改。

### ProcessDocumentApplicationService 集成分析

**文件：** `src/main/java/io/github/spike/myai/ingest/application/service/ProcessDocumentApplicationService.java:143`

```java
parseResult = documentTextParser.parse(document.filename(), sourceBytes);
```

异常传播链路：
1. `DocumentParserRouter.route()` 抛出 `UnsupportedDocumentFormatException`
2. TikaDocumentTextParser.parse() 的 `catch (Exception ex)` 重新抛出
3. ProcessDocumentApplicationService.handle() 的 `catch (Exception ex)` 捕获
4. `retryPolicy.decide(ex)` → 永久错误
5. `documentRepository.markFailed(...)` → 文档状态变为 FAILED，errorCode = "UnsupportedDocumentFormatException"，errorMessage = "不支持的文件格式: csv"

**415 状态码映射：** 在异步处理架构中，文档通过 Worker 处理。UnsupportedDocumentFormatException 导致 markFailed，错误信息存储在文档记录中。若需要在上传时同步返回 415，需在 `DocumentIngestController` 中添加格式预校验 — 这是可选的增强，不阻塞本 story 核心目标。

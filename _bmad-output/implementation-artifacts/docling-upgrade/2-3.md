# Story 2.3: 实现 DoclingDocumentParser 核心解析器

Status: done

## Story

As a 后端开发者，
I want 实现 DoclingDocumentParser 调用 DoclingServeApi，
So that 系统能够解析 8 种文档格式并产出 pre-chunked 结果，统一所有格式的解析路径。

## Acceptance Criteria

1. 新建 `DoclingDocumentParser`（infrastructure adapter），实现 `DocumentTextParser` 端口，位于 `ingest/infrastructure/parser/`。
2. 注入 `DoclingServeApi`（Arconia 自动配置 Bean），构造器注入，禁止 `@Autowired` 字段注入。
3. `parse()` 方法将文件内容 Base64 编码，构造 `FileSource`，调用 `DoclingServeApi.chunkSourceWithHybridChunker()`。
4. 配置 `HybridChunkerOptions`：`maxTokens=512`，`mergePeers=true`（硬编码，Story 4.1 再配置化）。
5. 从 `ChunkDocumentResponse` 映射 `DocumentParseResult`：
   - `cleanedMarkdown` 来自 `documents[0].content.markdownContent`
   - `processingMetadata` 为自构建的 JSON（schema_version + stable + conditional + best_effort）
6. 从 `Chunk` 映射 `ChunkMetadata`：使用 `ChunkMetadata.of()` 工厂方法，headings 来自 `chunk.getHeadings()`，pageNumber 来自 `chunk.getPageNumbers().getFirst()`（若为空则 0），contentType 从 Docling 原始类型映射。
7. 全部 8 种格式（PDF/DOCX/PPTX/XLSX/图片/MD/HTML/TXT）可产出非空 `DocumentParseResult`。
8. `DoclingServeApi` 的类型不暴露到 `DoclingDocumentParser` 以外（adapter 封装隔离）。
9. `DoclingDocumentParser` 不加 `@Component` 注解——由 `ProcessDocumentApplicationService` 的现有依赖注入机制决定是否使用（当前 Tika parser 是 `@Component`，Docling parser 替代后由 Story 3.1 路由切换时决定 Bean 注册方式）。**本 Story 暂加 `@Component`，与 Tika parser 共存**，通过 `@Qualifier("docling")` 区分。
10. 编写 `DoclingDocumentParserTest` 单元测试，mock `DoclingServeApi`，覆盖：正常解析、空内容拒绝、API 异常传播。
11. 编译通过：`mvn clean compile` 无错误。
12. 全量测试通过：`mvn "-Dtest=!MyAiApplicationTests" test` 无回归。

## Dev Notes

### Docling Serve API 接口（Arconia 0.20.0 提供）

**核心 API 签名**（`ai.docling.serve.api.DoclingServeApi`）：

```java
public interface DoclingServeApi {
    HealthCheckResponse health();
    ConvertDocumentResponse convertSource(ConvertDocumentRequest request);
    ChunkDocumentResponse chunkSourceWithHybridChunker(HybridChunkDocumentRequest request);
    ChunkDocumentResponse chunkSourceWithHierarchicalChunker(HierarchicalChunkDocumentRequest request);
}
```

**本 Story 使用 `chunkSourceWithHybridChunker`**（一步到位：convert + chunk）。

### 请求构造链

```java
// 1. 文件源
FileSource source = FileSource.builder()
        .base64String(Base64.getEncoder().encodeToString(content))
        .filename(filename)
        .build();

// 2. 混合分块选项（Story 4.1 再配置化）
HybridChunkerOptions chunkerOptions = HybridChunkerOptions.builder()
        .maxTokens(512)
        .mergePeers(true)
        .build();

// 3. 请求体
HybridChunkDocumentRequest request = HybridChunkDocumentRequest.builder()
        .source(source)
        .includeConvertedDoc(true)  // 需要 markdownContent
        .chunkingOptions(chunkerOptions)
        .build();

// 4. 调用
ChunkDocumentResponse response = doclingServeApi.chunkSourceWithHybridChunker(request);
```

### 响应数据结构

**ChunkDocumentResponse**：
```
chunks: List<Chunk>        ← chunk 列表
documents: List<Document>  ← convert 结果（需 includeConvertedDoc=true）
processingTime: Double
```

**Chunk**（每个分块）：
```
filename: String
chunkIndex: int
text: String              ← chunk 正文
rawText: String (nullable)
numTokens: Integer
headings: List<String>    ← 面包屑标题链 → ChunkMetadata.headings
captions: List<String>
docItems: List<String>
pageNumbers: List<Integer> ← 页码列表 → 取 first → ChunkMetadata.pageNumber
metadata: Map<String, Object>
```

**Document**（convert 结果）：
```
kind: String (nullable)
content: ExportDocumentResponse  ← 包含 markdownContent
status: String
errors: List<ErrorItem>
```

**ExportDocumentResponse**（文档内容）：
```
filename: String
markdownContent: String (nullable)  ← 就是 cleanedMarkdown 的来源
jsonContent: DoclingDocument (nullable)
htmlContent: String (nullable)
textContent: String (nullable)
doctagsContent: String (nullable)
```

### ChunkMetadata 映射策略

```java
private ChunkMetadata mapChunkMetadata(Chunk doclingChunk) {
    List<String> headings = doclingChunk.getHeadings();     // 可能为 null/empty
    int pageNumber = 0;
    List<Integer> pageNumbers = doclingChunk.getPageNumbers();
    if (pageNumbers != null && !pageNumbers.isEmpty()) {
        pageNumber = pageNumbers.getFirst();
    }
    // contentType 映射：本阶段默认 PARAGRAPH，后续可从 chunk metadata 细化
    ChunkContentType contentType = ChunkContentType.PARAGRAPH;

    return ChunkMetadata.of(headings, pageNumber, contentType);
}
```

**关键：使用 `ChunkMetadata.of()` 工厂方法**（Story 2.1 创建），它会：
- headings null → 空 list
- 过滤 null 和空白字符串元素
- contentType null → PARAGRAPH
- pageNumber 负数 → 抛异常

### processingMetadata 构建策略

Docling 响应不再提供 Tika 的 `Metadata` 对象，需要自行构建：

```java
private String buildProcessingMetadata(String filename, String cleanedMarkdown) {
    Map<String, Object> root = new LinkedHashMap<>();
    root.put("schema_version", "v1");

    Map<String, Object> stable = new LinkedHashMap<>();
    stable.put("source_file", filename);
    stable.put("file_ext", DocumentParserRouter.fileExtension(filename));
    stable.put("mime_type", "application/octet-stream"); // Docling 不提供精确 MIME
    stable.put("quality", "high");
    stable.put("created_at", clock.instant().toString());
    root.put("stable", stable);

    Map<String, Object> conditional = new LinkedHashMap<>();
    // 从 cleanedMarkdown 提取前 3 个 heading
    List<String> headings = extractTitleOutlineSample(cleanedMarkdown);
    if (!headings.isEmpty()) {
        conditional.put("primary_title", headings.getFirst());
        conditional.put("title_outline_sample", headings);
    }
    if (!conditional.isEmpty()) {
        root.put("conditional", conditional);
    }

    root.put("best_effort", Map.of());

    return objectMapper.writeValueAsString(root);
}
```

**注意**：`DocumentParserRouter.fileExtension()` 是 static 方法，可直接调用。`extractTitleOutlineSample()` 可从 `ProcessingMetadataBuilder` 复用正则逻辑。

### 时间获取

**禁止直接调用 `Instant.now()`**——必须通过注入的 `Clock` 获取时间。

```java
private final Clock clock;  // 构造器注入
// ...
stable.put("created_at", clock.instant().toString());
```

构造器模式（对齐项目规范）：
- public `@Autowired` 构造器：注入 `DoclingServeApi` + `ObjectMapper` + `IngestProperties` + 默认 `Clock.systemUTC()`
- package-private 构造器：接受 `Clock` 参数供测试注入

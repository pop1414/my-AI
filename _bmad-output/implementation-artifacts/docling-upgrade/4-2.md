# Story 4.2: Micrometer 指标埋点

Status: review

## Story

As a 系统运维者，
I want 基本观测指标（docling.parse.duration / docling.parse.errors / docling.chunk.count）埋入 DoclingDocumentParser 和 DoclingDocumentChunker，
so that 能够监控 Docling 解析性能与错误率，快速定位问题，确保 NFR-1（≤5s）达标。

## Acceptance Criteria

1. `DoclingDocumentParser.parse()` 执行后记录 `docling.parse.duration` 指标（Timer 类型，标签 `format` = 文件扩展名小写，如 pdf/docx/md）
2. `DoclingDocumentParser.parse()` 抛出 `DoclingPermanentException` 时记录 `docling.parse.errors` 指标（Counter 类型，标签 `errorType=permanent`）
3. `DoclingDocumentParser.parse()` 抛出 `DoclingTransientException` 时记录 `docling.parse.errors` 指标（Counter 类型，标签 `errorType=transient`）
4. `DoclingDocumentChunker.chunk()` 执行后记录 `docling.chunk.count` 指标（DistributionSummary 类型，标签 `format` 固定为 `markdown`）
5. Markdown 短路路径（`.md`/`.markdown`/`.mdown`/`.mkd`）成功时仍记录 `parse.duration`（format=md），失败时（`IllegalStateException`）不记录 `parse.errors`（非 Docling 错误）
6. 指标遵循 Micrometer 命名约定（小写点分隔），标签值使用枚举常量的 lowercase
7. 新增测试验证 Timer 计数/总时间、Counter 计数、DistributionSummary 计数与标签正确性
8. 编译通过：`mvn clean compile` 零错误
9. 存量测试通过：DoclingDocumentParserTest + DoclingDocumentChunkerTest 零失败

## Dev Notes

### 架构模式参考

**Pattern 5: Micrometer 指标命名模式（architecture.md）：**

| 指标名 | 类型 | 标签 | 说明 |
|--------|------|------|------|
| `docling.parse.duration` | Timer | `format` | 解析耗时 |
| `docling.parse.errors` | Counter | `errorType` (permanent/transient) | 错误计数 |
| `docling.chunk.count` | DistributionSummary | `format` | 分块数量分布 |

- 命名遵循 Micrometer 约定（小写点分隔）
- 标签值使用枚举常量的 lowercase

### 现有 Metrics 模式

**IngestMetrics.java（application/monitoring/）：**
- 使用 `Counter.builder("myai.ingest.*").description(...).register(meterRegistry)` 模式
- 构造器注入 `MeterRegistry`
- 命名前缀 `myai.ingest.*`

**本 story 的指标命名前缀是 `docling.*`**（不是 `myai.ingest.*`），与架构文档 Pattern 5 一致。这些指标是 Docling 适配器层的内部观测指标，不属于 application 层的业务指标聚合。

### 实现决策：指标放置位置

**决策：指标直接在 adapter 类（DoclingDocumentParser / DoclingDocumentChunker）内部注册和记录。**

理由：
1. 架构文档 Pattern 5 明确将这三个指标定义在 Docling adapter 层
2. Timer 需要方法级的开始/结束时间信息，放在外部类会增加不必要的复杂度
3. 与现有 `IngestMetrics`（application 层业务指标）形成层次分离：业务指标 vs 技术指标
4. 不新建单独的 `DoclingMetrics` 类 — 三个指标分属两个 adapter，单独类反而增加间接层

### Timer 记录方式（推荐方案）

**DoclingDocumentParser — `meterRegistry` 字段 + `Timer.Sample` + 预注册 Counter：**

```java
// 字段
private final MeterRegistry meterRegistry;
private final Counter parseErrorsPermanent;
private final Counter parseErrorsTransient;

// 构造器中
this.meterRegistry = meterRegistry;
this.parseErrorsPermanent = meterRegistry.counter("docling.parse.errors", "errorType", "permanent");
this.parseErrorsTransient = meterRegistry.counter("docling.parse.errors", "errorType", "transient");
```

```java
// parse() 方法中
String format = isMarkdownFilename(filename) ? "md" : DocumentParserRouter.fileExtension(filename);
Timer.Sample sample = Timer.start(meterRegistry);
try {
    if (isMarkdownFilename(filename)) {
        return mapMarkdownSourceToParseResult(filename, content);
    }
    ConvertDocumentResponse response = callDoclingApi(filename, content);
    return mapToDocumentParseResult(filename, response);
} catch (IllegalStateException ex) {
    throw ex;  // 非 Docling 错误，不记录 parse.errors
} catch (DoclingPermanentException ex) {
    parseErrorsPermanent.increment();
    throw ex;
} catch (DoclingTransientException ex) {
    parseErrorsTransient.increment();
    throw ex;
} catch (...) {
    // ... 现有异常处理逻辑不变 ...
} finally {
    sample.stop(meterRegistry.timer("docling.parse.duration", "format", format));
}
```

**说明：**
- `MeterRegistry` 存为字段（而非预注册 Timer），因为 `format` 标签是动态值（每次调用不同），需用 `meterRegistry.timer(name, tags)` 运行时查找/创建
- Counter 的标签值固定（permanent/transient），可在构造器中预注册，避免运行时 lookup
- `Timer.Sample` 在方法入口启动，在 finally 块中 stop，覆盖所有路径（含 Markdown 短路）
- `DocumentParserRouter.fileExtension(filename)` 是静态方法，可直接调用

**DoclingDocumentChunker — 预注册 `DistributionSummary`：**

```java
// 字段
private final DistributionSummary chunkCountSummary;

// 构造器中
this.chunkCountSummary = DistributionSummary.builder("docling.chunk.count")
```


### format 标签值来源

- **parse.duration 的 format**：使用 `DocumentParserRouter.fileExtension(filename)` 获取文件扩展名小写（如 `pdf`, `docx`, `md`, `txt`）
  - 该方法是静态方法，已在 `DocumentParserRouter` 中定义
  - Markdown 短路路径：format = `md`
- **chunk.count 的 format**：固定为 `markdown`（chunker 的输入始终是 Markdown 文本）

### Markdown 短路路径的指标处理

`parse()` 方法中 Markdown 短路路径（130-132 行）：
```java
if (isMarkdownFilename(filename)) {
    return mapMarkdownSourceToParseResult(filename, content);
}
```

**AC#5 的含义拆解：**
- 短路路径不调用 Docling API，但仍应记录 `parse.duration`（format=md），因为这是"解析"操作的总耗时
- 如果短路路径抛出 `IllegalStateException`（内容为空等），不记录 `parse.errors`（非 Docling 错误）

**实现方式：** Timer.Sample 需要包裹整个 `parse()` 方法体（包括短路路径和 Docling 调用路径），但 Counter 只在 Docling 异常路径触发。

# Story 3.2: 删除 Tika 全部依赖和代码

Status: ready-for-dev

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a 后端开发者，
I want 删除 Tika 全部依赖和代码，
So that 项目构建体积减少，依赖安全风险降低，不再维护两套解析逻辑。

## Acceptance Criteria

1. `pom.xml` 中无 `tika-core`、`tika-parsers-standard-package` 依赖，无 `tika.version` 属性。
2. 删除 `TikaDocumentTextParser`（~180 行，含 3 个 `@Deprecated` 方法：`parseWithTika`、`parseNativeMarkdown`、`parseNativeHtml`）。
3. 删除 `TikaParseContextFactory` 和 `NoOpEmbeddedDocumentExtractor`。
4. 删除 `HtmlSemanticCleaner` 和 `HtmlToMarkdownRenderer` — **已在 Story 2.5 完成，本 story 无需操作**。
5. `TextCleaningService` 中 `@Deprecated` 的 `cleanHtml()` 和 `toMarkdown()` 方法一并删除；类 Javadoc 中对 `TikaDocumentTextParser` 的引用同步清理。
6. `ProcessingMetadataBuilder` 成为死代码（唯一调用方为 `TikaDocumentTextParser`），**一并删除**，其测试类 `ProcessingMetadataBuilderTest` 同步删除。
7. `DoclingDocumentParser` 第 292 行对 `textCleaningService.toMarkdown()` 的调用修复：html_content 降级路径直接返回原始 HTML（`toMarkdown` 本就是 pass-through 桩），同时清理 Javadoc 中对 `TikaDocumentTextParser` 的 `@link` 引用（第 49 行）。
8. `DocumentTextParser` 端口接口 Javadoc 中移除 `TikaDocumentTextParser` 实现引用（第 17 行）。
9. 删除 `TikaDocumentTextParserTest` 和 `TikaParseContextFactoryTest` 测试类。
10. `IngestCleaningGoldenSamplesTest`：删除所有引用 `TikaDocumentTextParser` 的 `@Disabled` 测试方法（4 个引用 cleanHtml/toMarkdown 的方法），保留 `readme_shouldDocumentRegressionAcceptanceAnchors` 测试（该测试不依赖 Tika 代码）和 `@Disabled` 的 parse 测试（3 个，Story 4.3 重建基线时处理）。移除 `@SuppressWarnings("deprecation")` 注解（无 Deprecated 调用残留）。
11. 代码中无 `tika` 或 `org.apache.tika` 引用：`grep -ri "tika\|org\.apache\.tika" src/ pom.xml` 无匹配。
12. 编译通过：`mvn clean compile` 无错误。
13. 存量测试通过：`mvn "-Dtest=!MyAiApplicationTests" test` 无回归。

### ProcessingMetadataBuilder 死代码分析

**当前调用链（仅 TikaDocumentTextParser 使用）：**

```
TikaDocumentTextParser.parseWithTika()
    └→ processingMetadataBuilder.build(filename, metadata, cleanedMarkdown)
    └→ TikaParseContextFactory 创建 ParseContext

TikaDocumentTextParser.parseNativeMarkdown() / parseNativeHtml()
    └→ processingMetadataBuilder.build(filename, metadata, cleanedMarkdown)
```

**DoclingDocumentParser 的替代方案：**

DoclingDocumentParser 第 354-393 行有自己的 `buildProcessingMetadata` 方法，结构类似但不依赖 Tika Metadata 类：
- stable 层：source_file、file_ext、mime_type（硬编码 "application/octet-stream"）、quality、created_at（使用 Clock）
- conditional 层：仅 title_outline_sample（从 Markdown heading 正则提取）
- best_effort 层：空 Map

**两者的差异：**

| 字段 | ProcessingMetadataBuilder（Tika 版） | DoclingDocumentParser（当前版） |
|------|---------------------------------------|-------------------------------|
| mime_type | 从 Tika Metadata 读取 | 硬编码 "application/octet-stream" |
| language | 从 Tika Metadata 读取 | 不提取 |
| page_count | 从 Tika Metadata 读取 | 不提取 |
| primary_title | 优先 Tika title，降级 Markdown heading | 仅 Markdown heading |
| created_at | `Instant.now()` — 违反项目规则！ | `clock.instant()` — 正确 |

**注意：** ProcessingMetadataBuilder.buildStableMetadata() 第 52 行使用 `Instant.now().toString()`，违反项目规则"禁止直接调用 Instant.now()，必须通过注入的 Clock 获取时间"。删除该类同时消除了这个违规。

### DoclingDocumentParser.toMarkdown 调用修复

**当前代码（第 290-293 行）：**

```java
if (content.getHtmlContent() != null) {
    log.info("Docling md_content 为空，降级使用 html_content (status={})", status);
    return textCleaningService.toMarkdown(content.getHtmlContent());
}
```

**修复后：**

```java
if (content.getHtmlContent() != null) {
    log.info("Docling md_content 为空，降级使用 html_content (status={})", status);
    return content.getHtmlContent();
}
```

**理由：** `toMarkdown()` 在 Story 2.5 中已被改为 pass-through 桩（`return cleanedHtml`），直接返回原始 HTML。删除桩方法后，调用点直接返回 `content.getHtmlContent()`，行为完全等价。

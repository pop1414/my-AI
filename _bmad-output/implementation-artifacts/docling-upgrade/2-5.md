# Story 2.5: 实现 TextCleaningService 清洗逻辑

Status: review

## Story

As a 后端开发者，
I want 保留 TextCleaningService 的 cleanNativeMarkdown 方法，
So that Docling 产出的 Markdown 能够统一换行符、去除控制字符、压缩连续空行，确保输出格式一致。

## Acceptance Criteria

1. 在 `DoclingDocumentParser.mapToDocumentParseResult()` 中、`extractCleanedMarkdown()` 之后、`validateCleanedMarkdown()` 之前，调用 `TextCleaningService.cleanNativeMarkdown()` 对 Docling 原始输出进行清洗。
2. `TextCleaningService` 通过构造器注入 `DoclingDocumentParser`（遵循双构造器模式：public `@Autowired` + package-private 供测试注入）。
3. 清洗逻辑不暴露到 `DoclingDocumentParser` 外部——`cleanNativeMarkdown` 调用仅在 `mapToDocumentParseResult` 内部。
4. 删除 `TextCleaningService` 中的 `cleanHtml`、`toMarkdown`、`cleanText` 三个公共方法。
5. 删除 `HtmlSemanticCleaner.java` 和 `HtmlToMarkdownRenderer.java`（被 `cleanHtml`/`toMarkdown` 独占引用，删除后成为孤立代码）。
6. 删除 `MarkdownTextCleaner` 中的 `cleanConvertedMarkdown` 和 `cleanText` 方法（仅被 `toMarkdown` 调用，删除后成为死代码）。
7. `TextCleaningService` 精简后仅保留：`cleanNativeMarkdown`（公共）+ `repairMarkdownStructure`（包级私有静态代理）。
8. `TextCleaningServiceTest` 中与 `cleanHtml`/`toMarkdown`/`cleanText` 相关的测试用例被删除，`cleanNativeMarkdown` 相关测试保留。
9. 编译通过：`mvn clean compile` 无错误。
10. 相关测试通过：`mvn "-Dtest=TextCleaningServiceTest,DoclingDocumentParserTest" test` 无回归。
11. 全量测试通过：`mvn "-Dtest=!MyAiApplicationTests" test` 无回归。


### cleanNativeMarkdown 清洗行为

**文件**：`MarkdownTextCleaner.cleanNativeMarkdown()`

清洗步骤（按顺序）：
1. `CRLF → LF`、`CR → LF` 换行符统一
2. Unicode 兼容字符归一化（`⼀` → `一` 等 CJK 部首映射）
3. 控制字符移除（保留 `\n` 和 `\t`）
4. 不可见格式字符移除（BOM、零宽字符等）
5. 逐行处理：
   - 围栏代码块内部：仅 strip 尾部空白
   - 缩进代码行：仅 strip 尾部空白
   - 普通行：移除图片文件名、图片 URL 行、file:// URL 行、页面 chrome 噪音行
   - 危险 HTML 标签清除（`<script>`、`<style>`、`<iframe>` 等，代码块内除外）
6. 连续 3+ 空行压缩为 2 空行
7. 首尾 trim

### DoclingDocumentParser 集成点

**当前 `mapToDocumentParseResult` 方法**：

```java
private DocumentParseResult mapToDocumentParseResult(String filename, ChunkDocumentResponse response) {
    String cleanedMarkdown = extractCleanedMarkdown(response);
    validateCleanedMarkdown(cleanedMarkdown);                    // ← 在此之前插入清洗
    String processingMetadata = buildProcessingMetadata(filename, cleanedMarkdown);
    return new DocumentParseResult(cleanedMarkdown, processingMetadata);
}
```

**修改后**：

```java
private DocumentParseResult mapToDocumentParseResult(String filename, ChunkDocumentResponse response) {
    String rawMarkdown = extractCleanedMarkdown(response);
    String cleanedMarkdown = textCleaningService.cleanNativeMarkdown(rawMarkdown);  // ← 新增
    validateCleanedMarkdown(cleanedMarkdown);
    String processingMetadata = buildProcessingMetadata(filename, cleanedMarkdown);
    return new DocumentParseResult(cleanedMarkdown, processingMetadata);
}
```

**注意**：`validateCleanedMarkdown` 校验的是清洗后的内容（blank 检查 + 长度限制），清洗步骤放在校验之前是正确的——如果清洗后内容为空，应该报错。

### 关键约束

- **TextCleaningService 保持 `@Component`** — Spring 管理的 Bean，构造器注入到 DoclingDocumentParser
- **清洗在 Parser 内部、映射之前** — 不暴露清洗逻辑到 DoclingDocumentParser 外部
- **退出条件**：黄金样本清洗前后 diff 为零差异时可移除（记录为 no-op）
- **DoclingDocumentParser 是唯一引用 DoclingServeApi 的类** — TextCleaningService 不直接接触 Docling API
- **构造器注入遵循双构造器模式** — public `@Autowired` 注入所有依赖，package-private 供测试注入 Clock

# Story 2.1: 创建 ChunkMetadata 值对象

Status: done

## Story

As a 后端开发者，
I want 创建 ChunkMetadata 值对象替代 SourceHint，
So that chunk 携带结构化的 metadata（headings 面包屑、pageNumber、contentType），下游检索能统一利用这些信号。

## Acceptance Criteria

1. 新建 `ChunkMetadata` record（`headings: List<String>`, `pageNumber: int`, `contentType: ChunkContentType`），位于 `ingest/domain/model/`。
2. `headings` 字段在 compact constructor 中做防御性拷贝：`Collections.unmodifiableList(new ArrayList<>(headings))`，null 归一化为空 list。
3. 新建 `ChunkContentType` 枚举（domain 层，零框架注解）：`PARAGRAPH`, `TABLE`, `LIST_ITEM`, `CODE_BLOCK`, `HEADING`。
4. `headings` 空 list 合法（TXT 格式场景），`pageNumber` 默认 0 表示未知，`contentType` 默认 `PARAGRAPH`。
5. `SourceHint` 暂不删除（后续 Story 3.2 统一清理），本 Story 只新增 `ChunkMetadata` + `ChunkContentType`。
6. 编写 `ChunkMetadataTest` 单元测试，覆盖防御性拷贝、空 list 合法性、默认值、不可变性。
7. 全量测试通过（`mvn "-Dtest=!MyAiApplicationTests" test`），无回归。

**关键差异：SourceHint vs ChunkMetadata**

| 维度 | SourceHint（现有） | ChunkMetadata（新增） |
|------|-------------------|---------------------|
| 数据模型 | `heading: String` + `rawValue: String` | `headings: List<String>` + `pageNumber: int` + `contentType: ChunkContentType` |
| 语义 | 单一标题字符串 | 面包屑标题链 + 页码 + 内容类型 |
| 来源 | Java 侧启发式 chunker 产出 | Docling Serve server-side 产出 |
| 存储序列化 | JSON `{"heading":"..."}` | 待后续 Story 确定（PgVectorDocumentVectorIndexer 更新时决定） |

### 架构约束

- **本 Story 所有新文件在 domain/model/ 层**，零框架注解（禁止 `@Service`、`@Autowired`、`jakarta.persistence.*`、`org.springframework.*`）
- `ChunkMetadata` 是纯 Java record + 枚举，只依赖 `java.util.*`
- record compact constructor 只做校验和防御性拷贝，不做默认值填充的等价转换（null → empty list 是归一化，不是默认值填充）
- 遵循项目 record 规范：`.headings()` 不是 `.getHeadings()`

### 为什么不删除 SourceHint

本 Story 范围限于**新增** ChunkMetadata + ChunkContentType。SourceHint 的删除和全量替换涉及 15+ 个文件（见 architecture.md 级联改动面），分散在 Story 2.2、3.2、3.3、3.4 中按编译器驱动策略逐层处理。一次性改所有引用方会增加 commit 风险且偏离"一次提交只做一件事"原则。

### 与后序 Story 的关系

- **Story 2.2**（简化 DocumentParseResult）：不涉及 ChunkMetadata，但删除 rawXhtml/cleanedHtml 字段
- **Story 2.3**（DoclingDocumentParser）：将产出 `ChunkMetadata` 实例，从 Docling 响应映射 headings/pageNumber/contentType
- **Story 3.3**（删除 Java chunker）：删除 `ChunkWindowAssembler` 等 SourceHint 的生产者
- **Story 3.4**（移除 DocumentChunker 端口）：将 `DocumentChunk.sourceHint` 替换为 `chunkMetadata`，`SourceHint` 最终删除

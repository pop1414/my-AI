# Story 2.2: 简化 DocumentParseResult 字段

Status: done

## Story

As a 后端开发者，
I want 删除 DocumentParseResult 中的 rawXhtml / cleanedHtml 字段，
So that 解析结果只保留 cleanedMarkdown 和 processingMetadata，减少不必要的存储开销（NFR-2：artifact 存储减少 ≥20%）。

## Acceptance Criteria

1. `DocumentParseResult` record 删除 `rawXhtml` 和 `cleanedHtml` 字段，仅保留 `cleanedMarkdown` 和 `processingMetadata`。
2. compact constructor 仅校验 `cleanedMarkdown` 非空（逻辑不变）。
3. `TikaDocumentTextParser` 中所有 `new DocumentParseResult(...)` 调用改为 2 参数形式（`rawXhtml`/`cleanedHtml` 局部变量保留，它们仍被 `TextCleaningService` 使用，只是不再存入结果）。
4. `LocalDocumentProcessingArtifactStorage` 和 `S3DocumentProcessingArtifactStorage` 删除 `raw.xhtml`/`cleaned.html` 的条件写入逻辑、相关常量和配置字段。
5. `IngestProperties.Artifacts` 删除 `keepRawXhtml` 和 `keepCleanedHtml` 字段，`application.yaml` 删除对应配置项。
6. 所有构造 `DocumentParseResult` 的测试文件改为 2 参数形式，删除对 `rawXhtml()`/`cleanedHtml()` 的断言。
7. `DocumentTextParser` 和 `DocumentProcessingArtifactStorage` 端口接口的 javadoc 更新，移除对 `raw.xhtml`/`cleaned.html` 的引用。
8. `TextCleaningService`、`HtmlSemanticCleaner`、`HtmlToMarkdownRenderer` **本 Story 不删除**（Story 3.2 统一清理 Tika 代码），仅更新 javadoc 中对 artifact 名称的引用。
9. 编译通过：`mvn clean compile` 无错误。
10. 全量测试通过：`mvn "-Dtest=!MyAiApplicationTests" test` 无回归。

## Dev Notes

### 当前 DocumentParseResult 状态

**文件**：`src/main/java/io/github/spike/myai/ingest/domain/model/DocumentParseResult.java`

当前是 4 字段 record：
```java
public record DocumentParseResult(
    String rawXhtml,           // ← 删除
    String cleanedHtml,        // ← 删除
    String cleanedMarkdown,    // ← 保留
    String processingMetadata  // ← 保留
)
```

compact constructor 只校验 `cleanedMarkdown` 非空，删除字段后该逻辑不变。

### TikaDocumentTextParser 管道现状

**文件**：`src/main/java/io/github/spike/myai/ingest/infrastructure/parser/TikaDocumentTextParser.java`

三条解析路径均构造 `DocumentParseResult`：
- `parseWithTika()`：`rawXhtml` → `cleanHtml()` → `cleanedHtml` → `toMarkdown()` → `cleanedMarkdown` → 构造 4 参数结果
- `parseNativeMarkdown()`：跳过 Tika，直接 `cleanNativeMarkdown()`，构造 4 参数结果（前两参数为空字符串 `""`）
- `parseNativeHtml()`：`cleanHtml()` → `toMarkdown()` → 构造 4 参数结果

**关键洞察**：`rawXhtml` 和 `cleanedHtml` 是 `TextCleaningService` 管道的中间值。删除字段 ≠ 删除中间步骤。这三条路径中的 `textCleaningService.cleanHtml()` 和 `textCleaningService.toMarkdown()` 调用**必须保留**——它们产出 `cleanedMarkdown` 的唯一路径。

### Storage 适配器改动面

`LocalDocumentProcessingArtifactStorage` 和 `S3DocumentProcessingArtifactStorage` 都有：
- `keepRawXhtml` / `keepCleanedHtml` 布尔字段（从 `IngestProperties.Artifacts` 读取）
- `saveVersion()` 中的条件写入逻辑（`if (keepRawXhtml && ...) write raw.xhtml`）

这些全部删除。`keepParseResultJson` 保留不变（parse-result.json 由 `processingMetadata()` 产出，与删除的字段无关）。

### IngestProperties.Artifacts 改动

```java
// Before
public static class Artifacts {
    private long maxReadBytes = 2_000_000L;
    private boolean keepRawXhtml = false;      // ← 删除
    private boolean keepCleanedHtml = false;    // ← 删除
    private boolean keepParseResultJson = true; // ← 保留
}

// After
public static class Artifacts {
    private long maxReadBytes = 2_000_000L;
    private boolean keepParseResultJson = true;
}
```

### TextCleaningService 不删除的理由

Story 2.2 的范围是**删除 DocumentParseResult 的两个字段**，不是删除 Tika 解析管道。`TextCleaningService.cleanHtml()` 和 `toMarkdown()` 仍被 `TikaDocumentTextParser` 使用，是产出 `cleanedMarkdown` 的中间步骤。

删除 Tika 全部代码（含 TextCleaningService 的 `cleanHtml`/`toMarkdown`、HtmlSemanticCleaner、HtmlToMarkdownRenderer）是 **Story 3.2** 的职责。

# Story 3.3: 删除 Java 侧 chunker，实现 DoclingDocumentChunker

Status: review

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a 后端开发者，
I want 删除 Java 侧 chunker 并实现 DoclingDocumentChunker 替换，
So that 分块逻辑由 Docling Serve HybridChunker 完成（论文验证 faithfulness 97.59），同时保持 DocumentChunker 端口作为转换与分块的架构边界。

## Acceptance Criteria

1. 删除 `StructuredFallbackDocumentChunker`（~260 行）、`MarkdownSegmenter`、`HeadingContextExtractor`、`ChunkWindowAssembler`。
2. 删除 `infrastructure/chunking/` 目录（全部文件清空后删除目录）。
3. 删除 `StructuredFallbackDocumentChunkerTest` 测试类。
4. 新建 `DoclingDocumentChunker`（infrastructure/chunking/ 下），实现 `DocumentChunker` 端口，注入 `DoclingServeApi`。
5. `DoclingDocumentChunker.chunk(String markdown)` 调用 `DoclingServeApi.chunkSourceWithHybridChunker`，请求体中 `convert_options.to_formats = [md]`，`chunking_options.max_tokens = 512`，`merge_peers = true`，`includeConvertedDoc = false`。
6. 从 `ChunkDocumentResponse.chunks` 提取分块结果，映射为 `List<DocumentChunk>`，每个 chunk 的 `text` → `DocumentChunk.content()`，chunk metadata → `DocumentChunk.chunkMetadata()`。
7. 映射 `ChunkMetadata`（headings 面包屑 / pageNumber / contentType），使用 `ChunkMetadata.of()` 工厂方法安全归一化。
8. 异常处理对齐 `DoclingDocumentParser`（4xx 永久失败，5xx/超时重试）。
9. `DocumentChunk` 的 `sourceHint` 字段迁移为 `chunkMetadata: ChunkMetadata`（含 `DocumentChunkPreview`、`PgVectorDocumentVectorIndexer`、`DocumentChunker` 端口 Javadoc 同步更新）。
10. 删除 `SourceHint` 类（迁移完成后无引用方）。
11. `DocumentChunker` 端口接口保留不变（方法签名 `List<DocumentChunk> chunk(String text)` 不变）。
12. `ProcessDocumentApplicationService` 中的注入点无需修改（通过端口接口调用）。
13. 应用编译通过：`mvn clean compile` 无错误。
14. 存量测试通过：`mvn "-Dtest=!MyAiApplicationTests" test` 无回归。

## Dev Notes

### 关键发现：SourceHint → ChunkMetadata 迁移未完成

**现状：** Epic 2 的 Story 2.1 创建了 `ChunkMetadata` 值对象，但 **没有将 `DocumentChunk.sourceHint` 替换为 `DocumentChunk.chunkMetadata`**。

| 文件 | 当前字段 | 应有字段 |
|------|----------|----------|
| `DocumentChunk.java` | `SourceHint sourceHint` | `ChunkMetadata chunkMetadata` |
| `DocumentChunkPreview.java` | `SourceHint sourceHint` | `ChunkMetadata chunkMetadata` |
| `PgVectorDocumentVectorIndexer.java:115` | `chunk.sourceHint()` | `chunk.chunkMetadata()` |
| `ChunkWindowAssembler.java:67,77,85` | `SourceHint.heading(...)` | 删除（本 Story 删除整个文件） |

**影响：** `DoclingDocumentChunker` 需要产出 `DocumentChunk(content, ChunkMetadata)`，但当前 `DocumentChunk` 只接受 `SourceHint`。必须先完成迁移（Task 0）。

**决策：** 将 SourceHint → ChunkMetadata 迁移纳入本 Story，而非单独开 Story。理由：
1. 这是 DoclingDocumentChunker 的硬性前置依赖
2. Epic 架构文档（architecture.md §Pattern 3）已定义 ChunkMetadata 值对象模式
3. ChunkMetadata 类已就绪（Story 2.1 创建），只需替换引用
4. 改动面可控（4 个文件 + 删除 SourceHint）

### PgVectorDocumentVectorIndexer 存储格式变更

**当前代码（第 115-119 行）：**

```java
SourceHint sourceHint = chunk.sourceHint();
if (!sourceHint.isEmpty()) {
    metadata.put("sourceHint", sourceHint.toStorageValue());
}
```

**迁移后：**

```java
ChunkMetadata chunkMetadata = chunk.chunkMetadata();
if (!chunkMetadata.headings().isEmpty() || chunkMetadata.pageNumber() > 0) {
    metadata.put("chunkMetadata", serializeChunkMetadata(chunkMetadata));
}
```

**存储序列化：** 使用 JSON 格式 `{"headings":["h1","h2"],"pageNumber":3,"contentType":"PARAGRAPH"}`。

**⚠️ 向后兼容：** 存量向量数据库中已存储的 `sourceHint` 字段不会自动迁移。这是可接受的——存量 chunk 的 `sourceHint` 数据在向量检索中仅作辅助信号，新 chunk 使用 `chunkMetadata` 后质量更高。Story 4.3 黄金样本重建时会覆盖旧数据。

### DoclingDocumentChunker 设计

**文件：** `src/main/java/io/github/spike/myai/ingest/infrastructure/chunking/DoclingDocumentChunker.java`

**核心设计：** 与 DoclingDocumentParser 同构，但职责更单一 — 只负责分块，不负责转换。

```
DoclingDocumentChunker (Spring @Component)
├── chunk(String markdown) → List<DocumentChunk>
│   ├── Base64 编码 markdown
│   ├── 构造 HybridChunkDocumentRequest
│   │   ├── source: FileSource(base64, "input.md")
│   │   ├── options: ConvertDocumentOptions(to_formats=[MARKDOWN])
│   │   ├── chunkingOptions: HybridChunkerOptions(maxTokens=512, mergePeers=true)
│   │   └── includeConvertedDoc: false（不需要返回转换文档）
│   ├── 调用 DoclingServeApi.chunkSourceWithHybridChunker
│   ├── 从 response.chunks 提取分块
│   └── 映射为 List<DocumentChunk>
│       ├── Chunk.text() → DocumentChunk.content()
│       └── Chunk.headings/pageNumbers → ChunkMetadata.of() → DocumentChunk.chunkMetadata()
└── 异常处理（与 DoclingDocumentParser 对齐）
    ├── HttpClientErrorException 408/429 → DoclingTransientException
    ├── HttpClientErrorException 其余 → DoclingPermanentException
    ├── HttpServerErrorException → DoclingTransientException
    ├── ResourceAccessException → DoclingTransientException
    └── Exception → DoclingTransientException（保守策略）
```

**与 DoclingDocumentParser 的关键差异：**

| 维度 | DoclingDocumentParser | DoclingDocumentChunker |
|------|----------------------|----------------------|
| 端口 | DocumentTextParser | DocumentChunker |
| API 调用 | chunkSourceWithHybridChunker（转换+分块一步） | chunkSourceWithHybridChunker（仅分块） |
| 请求参数 | to_formats=[MD,HTML,TEXT,DOCTAGS], includeConvertedDoc=true | to_formats=[MD], includeConvertedDoc=false |
| 输出 | DocumentParseResult (cleanedMarkdown + metadata) | List<DocumentChunk> (text + chunkMetadata) |
| 依赖注入 | DoclingServeApi, ObjectMapper, IngestProperties, TextCleaningService, Clock | DoclingServeApi, IngestProperties |
| 清洗 | 需要 TextCleaningService.cleanNativeMarkdown | 不需要（输入已是清洗后的 Markdown） |
| processingMetadata | 需要构建 | 不需要（由 Parse 阶段产出） |

**⚠️ 注意：** DoclingDocumentParser 当前也调用 `chunkSourceWithHybridChunker`（而非 `convertSource`），这与 Epic 架构文档描述不同。实际实现中 DoclingDocumentParser 用 HybridChunker 一步完成转换+分块，但只使用 document.md_content（转换结果），忽略 chunks（分块结果）。DoclingDocumentChunker 则使用 chunks（分块结果），忽略 document content。

### 异常处理对齐

DoclingDocumentChunker 与 DoclingDocumentParser 使用完全相同的异常处理模式：

| 异常 | 场景 | Worker 行为 |
|------|------|------------|
| `DoclingPermanentException` | 4xx（除 408/429） | markFailed |
| `DoclingTransientException` | 5xx, 408, 429, 超时, 网络, 未知 | markRetry（最多 3 次） |

**⚠️ 关键：** `chunk()` 方法内部 catch 块中**不要调用 TextCleaningService**。输入已经是 `ProcessDocumentApplicationService` 传入的 `parseResult.cleanedMarkdown()`，已完成清洗。

### DocumentChunk 迁移细节

**当前 DocumentChunk：**

```java
public record DocumentChunk(String content, SourceHint sourceHint) {
    public DocumentChunk(String content, String sourceHint) {
        this(content, SourceHint.fromStorageValue(sourceHint));
    }
    public DocumentChunk {
        if (content == null) throw new IllegalArgumentException("content must not be null");
        if (sourceHint == null) sourceHint = SourceHint.none();
    }
}
```

**迁移后 DocumentChunk：**

```java
public record DocumentChunk(String content, ChunkMetadata chunkMetadata) {
    public DocumentChunk {
        if (content == null) throw new IllegalArgumentException("content must not be null");
        if (chunkMetadata == null) chunkMetadata = ChunkMetadata.of(null, 0, null);
    }
}
```

**⚠️ 删除 `DocumentChunk(String, String)` 辅助构造器** — 该构造器从存储值反序列化 SourceHint，迁移后不再需要。`DocumentChunkPreview` 有同模式的辅助构造器，一并清理。

**迁移后：**

```java
public record DocumentChunkPreview(
```

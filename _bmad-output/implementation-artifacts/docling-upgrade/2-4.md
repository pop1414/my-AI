# Story 2.4: 实现错误处理与重试逻辑

Status: review

## Story

As a 后端开发者，
I want 实现 DoclingParseException 异常层次和错误映射逻辑，
So that Docling 4xx 错误映射为永久失败（FAILED），5xx/网络超时映射为瞬时错误（重试），与现有 Worker 重试策略无缝对接。

## Acceptance Criteria

1. 在 `ingest/domain/model/` 下创建 `DoclingParseException` 异常基类（零框架注解），继承 `RuntimeException`。
2. 创建 `DoclingPermanentException` 继承 `DoclingParseException`，用于 4xx 错误和不支持的格式。
3. 创建 `DoclingTransientException` 继承 `DoclingParseException`，用于 5xx、超时、网络错误，保留 cause 链。
4. `DoclingDocumentParser` 捕获 Arconia 抛出的 HTTP 异常（`HttpClientErrorException` → 4xx，`HttpServerErrorException` → 5xx），映射为对应 Docling 异常。
5. `DoclingDocumentParser` 捕获连接超时 / `ResourceAccessException` 等网络异常，映射为 `DoclingTransientException`。
6. `RetryPolicy` 新增 `DoclingPermanentException` → 非瞬时（`transientError=false`）分类规则。
7. `RetryPolicy` 新增 `DoclingTransientException` → 瞬时（`transientError=true`）分类规则。
8. Worker 层（`ProcessDocumentApplicationService`）无需修改——异常通过 `RetryPolicy.decide()` 自动路由到 `markFailed` 或 `markRetry`。
9. 4xx 错误的 `errorCode` 为 `DOCLING_PERMANENT`，5xx/超时的 `errorCode` 为 `DOCLING_TRANSIENT`。
10. 编写单元测试：`DoclingDocumentParserTest` 新增错误映射测试用例；`RetryPolicyTest` 新增 Docling 异常分类测试。
11. 编译通过：`mvn clean compile` 无错误。
12. 全量测试通过：`mvn "-Dtest=!MyAiApplicationTests" test` 无回归。

## Dev Notes

### 现有 Worker 重试机制（不修改）

**ProcessDocumentApplicationService** 的错误处理链路：

```
parse() 抛出异常
  → catch (Exception ex)
    → retryPolicy.decide(ex) → RetryDecision(transientError, errorCode, errorMessage)
      → if transientError && retryCount < retryMax → markRetry（UPLOADED，指数退避）
      → else → markFailed（FAILED）
```

**关键约束**：`ProcessDocumentApplicationService` **不修改**。新增的 Docling 异常只需被 `RetryPolicy` 正确分类即可自动工作。

**现有 retryMax**：`Document.DEFAULT_RETRY_MAX = 3`（指数退避：1s, 2s, 4s + 0~300ms jitter）。

### RetryPolicy 当前分类逻辑

**文件**：`src/main/java/io/github/spike/myai/ingest/application/service/RetryPolicy.java`

`classify()` 方法按顺序匹配异常类型，首个匹配即返回。当前顺序：

1. `HttpStatusCodeException` → HTTP 状态码分类（408/429/5xx=transient，其他=fatal）
2. `WebClientResponseException`（反射）→ 同上
3. `TransientDataAccessException` / `SQLTransientException` / `SQLRecoverableException` → transient
4. `SocketTimeoutException` / `ConnectException` / `UnknownHostException` → transient
5. `IOException`（非 disk-full）→ transient
6. `IllegalArgumentException` → fatal

**新增规则插入位置**：
- `DoclingPermanentException` → 插在 `IllegalArgumentException` 之前（Rule 5.5）
- `DoclingTransientException` → 插在 `IOException` 之前（Rule 4.5）

### Arconia DoclingServeClient 异常行为

**文件**：Arconia `DoclingServeClient` 使用 Spring HTTP Interface（`@PostExchange`），底层为 `RestClient`。

当 Docling Serve 返回错误时，Spring `RestClient` 抛出：

| Docling Serve 响应 | Spring 异常 | 父类 |
|---|---|---|
| 4xx (400, 422, etc.) | `HttpClientErrorException` | `RestClientResponseException` → `RuntimeException` |
| 5xx (500, 503, etc.) | `HttpServerErrorException` | `RestClientResponseException` → `RuntimeException` |
| 连接超时 | `ResourceAccessException`（包装 `ConnectException`） | `AccessException` → `RuntimeException` |
| 读超时 | `ResourceAccessException`（包装 `SocketTimeoutException`） | `AccessException` → `RuntimeException` |

**这些异常由 Arconia 库抛出**，不是我们能控制的。`DoclingDocumentParser` 需要在 catch 块中显式捕获并映射。

### DoclingParseException 异常层次设计

```
DoclingParseException (domain/model/, extends RuntimeException)
├── DoclingPermanentException (4xx, 不支持的格式)  → errorCode: "DOCLING_PERMANENT"
└── DoclingTransientException (5xx, 超时, 网络)     → errorCode: "DOCLING_TRANSIENT"
```

**设计要点**：
- 三个类均在 `ingest/domain/model/` 包下，遵循六边形架构（domain 层定义异常）
- 零框架注解——只用 Java 标准库
- 中文 Javadoc，类级别含 `@author spike` + `@since 1.0.0`
- 构造器接收 `String message` + `Throwable cause`（保留原始异常链）
- `DoclingPermanentException` 额外携带 `httpStatusCode` 字段，供 `RetryPolicy` 生成精确的 errorCode

**DoclingPermanentException 签名**：

```java
public class DoclingPermanentException extends DoclingParseException {
    private final int httpStatusCode;

    public DoclingPermanentException(String message, int httpStatusCode, Throwable cause) {
        super(message, cause);
        this.httpStatusCode = httpStatusCode;
    }

    public int httpStatusCode() { return httpStatusCode; }
}
```

**DoclingTransientException 签名**：

```java
public class DoclingTransientException extends DoclingParseException {
    public DoclingTransientException(String message, Throwable cause) {
        super(message, cause);
    }
}
```

### DoclingDocumentParser 错误映射策略

**重写 `parse()` 方法的 catch 块**：

```java
@Override
public DocumentParseResult parse(String filename, byte[] content) {
    if (content == null || content.length == 0) {
        throw new IllegalStateException("empty source content");
    }

    try {
        ChunkDocumentResponse response = callDoclingApi(filename, content);
        return mapToDocumentParseResult(filename, response);
    } catch (IllegalStateException ex) {
        // 输入校验/响应校验错误（空内容、空 documents、null markdownContent、超长文本）
        // 这些是逻辑错误，不可重试
        throw ex;
    } catch (HttpClientErrorException ex) {
        // 4xx 客户端错误 → 永久失败（不重试）
        throw new DoclingPermanentException(
                "docling returned client error: " + ex.getStatusCode(),
                ex.getStatusCode().value(),
                ex);
    } catch (HttpServerErrorException ex) {
        // 5xx 服务端错误 → 瞬时错误（可重试）
        throw new DoclingTransientException(
                "docling returned server error: " + ex.getStatusCode(), ex);
    } catch (ResourceAccessException ex) {
        // 连接超时 / 读超时 → 瞬时错误（可重试）
        throw new DoclingTransientException("docling connection failed", ex);
    } catch (Exception ex) {
        // 其他未知异常 → 保守策略：视为瞬时错误（先尝试重试）
        throw new DoclingTransientException("unexpected docling error", ex);
    }
}
```

### RetryPolicy 修改策略

在 `classify()` 方法中新增两个规则，插入位置需注意匹配顺序：

```java
// 5.5) Docling 永久错误（4xx 客户端错误）
if (cause instanceof DoclingPermanentException ex) {
    return new RetryDecision(false, "DOCLING_PERMANENT_" + ex.httpStatusCode(), safeMessage(ex));
}
// 5.6) Docling 瞬时错误（5xx 服务端错误、超时、网络异常）
if (cause instanceof DoclingTransientException) {
    return new RetryDecision(true, "DOCLING_TRANSIENT", safeMessage(cause));
}
```

**插入位置**：在 `IOException` 块之后、`IllegalArgumentException` 块之前。

**errorCode 命名**：
- `DOCLING_PERMANENT_400` / `DOCLING_PERMANENT_422` — 含 HTTP 状态码，便于日志排查
- `DOCLING_TRANSIENT` — 统一标识，具体原因可从 errorMessage 获取

**新增 import**：
```java
import io.github.spike.myai.ingest.domain.model.DoclingPermanentException;
import io.github.spike.myai.ingest.domain.model.DoclingTransientException;
```

## 做得好的

1. **架构纪律堪称典范** — 六边形架构在整轮 Epic 中零违反。四个故事全部遵守了：端口接口不修改（AD-1）、RRF 对调用方透明（AD-2）、adapter 层内部消化异常（AD-3）。Story 2.4 ApplicationService 零改动切换到 Hybrid Search，@Primary 注入是最佳实践
2. **依赖链执行干净** — 4 个故事严格按 V9 迁移 → ScopeFilterBuilder → SparseRetrieval → HybridRRF 顺序执行，前置依赖正确就位，零返工
3. **NFR-2 零新依赖约束被严格遵守** — tsvector + GIN 是 PostgreSQL 原生，BM25 用 JdbcTemplate 直接 SQL，RRF 用 CompletableFuture + Map + Stream 全 JDK 标准库
4. **降级策略设计周全** — Hybrid 的容错覆盖 Dense 失败、Sparse 失败、双路失败三种场景，测试验证到位
5. **并行执行满足延迟约束** — NFR-1 要求 ≤200ms 增量，CompletableFuture 并行执行 Dense/Sparse 满足要求

## 关键洞察

1. **@Primary + 端口接口 = 零改动切换** — Hybrid Search 引入方式是六边形架构最佳实践
2. **重构先行（Story 2.2）为后续故事铺路** — ScopeFilterBuilder 让 SparseRetrieval 的 scope 过滤变成一行调用
3. **纯 SQL 在 infrastructure 层的力量** — JdbcTemplate 直接 SQL 不经过 Spring AI VectorStore，满足 BM25 需求且架构简洁
4. **RRF 融合算法工程实现标准** — k=60、等权重 0.5/0.5，遵循 Cormack 2009 论文
5. **测试断言质量是可提升的瓶颈** — 3/4 故事有测试初版断言错误，写测试时需更仔细验证预期值

## 做得好的

1. **三阶段分步交付策略奏效** — 3.1a（数据模型+加载器）→ 3.1b（指标计算器+执行器）→ 3.1c（三模式对比+报告），每阶段有独立可验证物，降低单次提交风险
2. **test-only 架构隔离彻底** — 11 个新文件全在 src/test/，零侵入生产代码，`mvn clean package -DskipTests` 完全不受影响
3. **虚拟线程一次到位** — Java 21 `Executors.newVirtualThreadPerTaskExecutor()` 应用正确，三模式并行执行零调试
4. **行动项追踪有效** — Epic 2 承诺的 Javadoc 和测试断言两项均有改善，跨 Epic 回顾机制被验证
5. **loadFromStream 设计灵活性** — 从 `load(String resourcePath)` 重构为增加 `loadFromStream(InputStream)` 重载，增强了可测试性
6. **NFR-2 零新外部依赖约束持续遵守** — Jackson（Spring Boot 测试自带）、JDK 标准库，无新依赖

## 需要关注的

1. **防御性编程仍需前置** — 9 个审查修复项中大部分（null 防护、负值校验、异常拆分）应在初版实现时就做到，而非等到 review 阶段
2. **QA pairs 使用占位符 doc_id** — 评测结果目前不反映真实检索质量，需用实际知识库文档 ID 更新
3. **样本量有限** — 20 条 QA pairs 作为 MVP 足够，但统计置信度有限
